# Delegate routing

## 判据

仅在用户明确提出委托、分流、独立审查或执行器选择时使用本判据。普通“继续”和已授权任务的执行不触发委托前置确认；决策已定不等于必须委托，执行器可用也不代表需要委托。可以在主会话继续完成工作。

在用户请求的范围内，有未定取舍时留在主会话；决策已定、只剩执行和查证时，结合独立审查价值、上下文与调用成本判断是否提议，不把下表当强制派活规则。

| 活的类型 | 分流 |
| --- | --- |
| 代码审查 / 找回归 / 安全审 | 可提议，只读 |
| 跨文件摸结构、梳理调用链 | 可提议，只读 |
| 复现 bug、定位根因、读栈 | 可提议，只读 |
| 单个 task 的实现（改文件 + 跑测试到绿） | 可提议 Codex，`--write` 须明确授权 |
| 批量机械改动（重命名、迁移、格式） | 可提议 Codex，`--write` 须明确授权 |
| 需求澄清 / 架构取舍 / 验收 Codex 交回来的东西 / 改一行 | **不派** |

绝不自动派：只提议，等用户一个明确的肯定答复再调。

用户直接给出明确委托命令或已经批准同一范围时，按该授权执行，不重复确认。写权限仍须用户明确授予，不因“继续”或执行器可用自行升级。

## 宿主、方向与基础条件

主会话宿主仅依据会话的可靠上下文；安装/认证缓存、可执行文件、模型名称或可能继承的环境变量不能证明宿主。宿主未知时不作自动方向提示。Codex 主会话不因 Codex 可用而提议 Codex→Codex；用户明确要求独立 Codex 审查时仍可执行。

Claude Code→Codex和Codex→Claude Code按用户明确的目标选择后端，不自动选择相反宿主。Codex 可用缓存只记录 Codex 基础条件，不能证明 Claude 可用；需要时用对应后端 doctor 核实，失败不换后端。没有每轮 Hook 提醒，基础条件由体检报告，路由由显式请求和本 skill 判断。

## 回来之后的纪律

- 不要 `cat` 整个过程日志（等于把省下的上下文重新灌回来）；要证据就按路径 `sed -n` 取几行。
- `--write` 回来无论成功或失败都必须看 git 验收块与真实 diff；失败不自动回滚，不能只信 Codex 的自述。
- `--write` 必须用户在该轮明确要求，模型不得自行升级。唯一例外：`/delegate:run` 参考文件（`references/run.md`）里写入授权的四个条件全部满足、并带 `--authorized-by <文件>` 时，视为本轮已授权；任一条不满足就回到本条。

调用 Bash 时，timeout 设为 `600000`。

主会话宿主与执行后端独立。审查入口 `/delegate:review` 默认仍是 Codex；用户明确选择 Claude Code 时用 `--backend claude-code`，限定 diff、模块或明确路径，不因宿主自动换后端。范围用 paths/base/changes 快捷参数或高级 context JSON；缺范围不扫描全项目。两个后端的 review 都只读，拒绝 write；Claude 另拒绝 effort。实现和机械修改用 `/delegate:run`，目前仅既有 Codex。两后端的模型/参数分开，失败不换后端，不把不同模型视角当作准确率证明。

Claude 仅走 Mac 本机 CLI、原有认证和 srt/Node 依赖；条件不足报告缺项，不安装/升级/登录、不静默切换认证或后端。共同审查报告区分执行与发现、列出未审和未验证内容；无输出/拒权/达限不当作无问题。宿主或模型无可靠证据则未知。审查者不得再次调用 delegate；共同结果不授权合并或交付。

纯 paths/module 默认读取 HEAD，未提交内容只有显式 changes 才纳入；untracked 须明确 include-untracked。固定提交 diff 使用 base/head；工作区 diff 使用 changes，不能混用。review --dry-run 仅无模型预览，不检查后端可用性、不产生审查结论。高级 context 与快捷范围参数互斥。源旧 `/delegate:delegate` 已改为 run/review，不更新安装缓存。

帮助见 `/delegate:help`，按后端体检见 `/delegate:doctor`。任务须在业务 Git 工作区执行。只读沙箱可能限制会写文件的测试；需要写入时另由用户明确授权。确认是行为指令，不是不可绕过的技术锁；同一范围已有授权时不重复索取。
