# Delegate routing

## 判据

判据不是「这活难不难」，而是「**这活里还有没有没定的决策**」。决策全定完、只剩执行和查证时，可以提议交给 Codex；还需要取舍判断时，留在 Claude。

| 活的类型 | 分流 |
| --- | --- |
| 代码审查 / 找回归 / 安全审 | 派，只读 |
| 跨文件摸结构、梳理调用链 | 派，只读 |
| 复现 bug、定位根因、读栈 | 派，只读 |
| 单个 task 的实现（改文件 + 跑测试到绿） | 派，`--write` |
| 批量机械改动（重命名、迁移、格式） | 派，`--write` |
| 需求澄清 / 架构取舍 / 验收 Codex 交回来的东西 / 改一行 | **不派** |

绝不自动派：只提议，等用户一个明确的肯定答复再调。

## 回来之后的纪律

- 不要 `cat` 整个过程日志（等于把省下的上下文重新灌回来）；要证据就按路径 `sed -n` 取几行。
- `--write` 回来无论成功或失败都必须看 git 验收块与真实 diff；失败不自动回滚，不能只信 Codex 的自述。
- `--write` 必须用户在该轮明确要求，模型不得自行升级。

调用 Bash 时，timeout 设为 `600000`。

执行入口使用 `/delegate:delegate`，帮助见 `/delegate:help`。任务须在业务 Git 工作区执行。只读沙箱可能限制会写文件的测试；需要写入时另由用户明确授权。确认是行为指令，不是不可绕过的技术锁。
