# v0.8.3: Filling gaps in the user documentation

[简体中文](../../releases/v0.8.3.md) | English

A patch release after v0.8.2 that **changes only user-facing documentation and help text; behavior is unchanged**. The interface description stays `1.3`; command options, deadlines, the result line, the result file and exit statuses are the same as in v0.8.2, and no migration is needed.

It follows a list of documentation gaps (ledger item S75) from the ecosystem lead, who read every plugin's documentation while writing a user handbook: places where a user following the documents would get stuck or misread them. After checking each item against v0.8.2, this release changes the seven places below.

## Fixes

- **Routing skill description**: the `delegate-routing` trigger description said "delegate to Codex or Claude Code" without separating review from execution; it now says Codex can review or execute, and Claude Code only performs read-only review. The opening of both READMEs was already correct and is unchanged.
- **One background rule for `--timeout`**: the READMEs, the plugin README, `references/run.md` and the script's `--help` said "use background mode above the host's foreground limit (600 seconds)", while the command description and the skill said "above 540 seconds". All now use the stricter wording: whenever `--timeout` (541–7200 seconds) is given, use the host's background mode ([run-longrun](../SPEC-run-longrun.md) S9). A run can take up to about `T + 30` seconds, so judging by 600 seconds would let runs above 570 seconds hit the foreground limit.
- **Installing and checking srt**: the prerequisites said "an installed srt 0.0.79" without naming its package. The root README now gives the npm package `@anthropic-ai/sandbox-runtime`, the install command and version checks for `srt`, `node` and `claude`, and the troubleshooting row for missing preconditions (127) points to it; the plugin README and the help name the package too.
- **`--write` does not commit**: "commands outside the sandbox (such as `git commit` in a worktree) are rejected; the caller commits" was only in the plugin README; the root README's write guidance and option table now say so.
- **Keeping acceptance evidence**: logs and result files are rotated (latest 50 groups; chain state 14 days), and nothing said what to do when evidence must be kept. The root README now explains it: for run, copy `<runId>.result.json` and `<runId>.answer`; for review, save the JSON report from standard output; quote only the log lines you need.
- **`git_probe_failed` in a repository without commits**: the prerequisites said review needs an existing commit, but the troubleshooting table lacked this diagnostic. A new row says it exits 127, also with `--dry-run`; the most common cause is a repository with no commits, which `--changes working-tree --include-untracked` does not get around, so commit once first; if commits exist, check `--base`/`--head`.
- **`/delegate:help` in sections and items**: `commands/help.md` was several long unbroken paragraphs; it is now split into entries, review scope, run, Claude backend, results and exit statuses, and migration, one item per line, and asks for answers in that shape. No content is dropped beyond statements repeated from the script's `--help`; the Codex rendering shrinks from 3993 bytes to about 3600, still within the 4000-byte limit.

## Not in this release

- Two other items in the ecosystem ledger are not this repository's documentation: the local main checkout sitting on an old branch is local machine state, and agent-relay still citing the removed `delegate:delegate` is for agent-relay to fix.
- A dedicated diagnostic for "repository has no HEAD" would be a behavior change and is not in this release; `git_probe_failed` remains the shared code for any failed internal Git query.

## Validation and known limitations

The script changes only one line of `--help` text; no logic or tests changed. Free validation still covers 328 Python, 53 shell and 19 eval checks; the command size test passes (`help.md` renders to about 3600 bytes); `claude plugin validate` passes for both the marketplace and the plugin. This release makes no paid calls. The other unverified items listed in v0.8.0 are unchanged.

## Update

Run `claude plugin update delegate@delegate-marketplace`, then open a new session or run `/reload-plugins`. Upgrading from v0.8.2 needs no migration.
