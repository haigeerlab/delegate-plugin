# v0.7.1: Reclaim commands started by Codex when a run is aborted

[简体中文](../../releases/v0.7.1.md) | English

A patch release after v0.7.0 that only fixes process cleanup when `/delegate:run` is aborted. The interface description stays `1.2`; command usage, options, the 540-second deadline, the result line and the state file are unchanged.

## Upgrade notes

Consumers that read delegate output (scripts, plugins, session workflows) should note two things:

1. **New exit status 125.** If the execution process cannot be reaped within the bound, `/delegate:run` prints `delegate: 执行进程未能回收，PID=…` (execution process could not be reaped) and exits 125 without a result line. Treat it as failure; success is still exit status 0 plus `status=done`.
2. **A few cleanup lines on stderr when aborted.** On deadline or TERM/INT/HUP, stderr gains lines starting with `delegate: 清理：…` (cleanup): the Codex descendants before the abort, and `无残留` (none left) or `仍有残留，PID=…` (survivors). stdout and the result line are unchanged.

## Fixes

- **Reclaim commands started by Codex on abort ([channel](../SPEC-channel.md) revision S41)**: each shell command Codex runs starts in a new session and process group. Previously an abort only cleaned up the Codex process group, so commands were adopted by init/launchd and kept running, and in write mode could still change the workspace after delegate reported completion. Now Codex is frozen first, all descendants are snapshotted along parent links, TERM goes to every descendant process group and to Codex as it is unfrozen, and what remains after one shared grace period of at most 2 seconds is killed.
- **The final wait is bounded**: reaping the execution process waits at most 5 seconds; if it cannot be reaped, its PID is reported and the exit status is 125, instead of hanging the host indefinitely. An interrupted wrapper waits at most 15 seconds for the execution process, then forces it to stop and waits at most 2 more seconds; a forced stop reports `执行进程超时未退出，已强制结束（PID=…），其后代可能残留。` (forced to stop; descendants may survive).
- **Cleanup results are reported truthfully**: the cleanup report of an abort is written to `<runId>.cleanup` in the process directory and relayed to stderr; the file follows the retention of its log.

## Validation and known limits

Free aggregate validation covers 253 Python cases (6 more than v0.7.0: 4 channel regressions and 2 in the new `reap-fake-endpoint` suite), 53 shell and 19 eval cases, and 20 loop-registered Python regression suites; `claude plugin validate` passes for the marketplace and the plugin. The regressions were first confirmed red on v0.7.0 code before the fix.

- Fake-codex regressions: descendants in another session are reclaimed on deadline and on TERM, INT and HUP, with a cleanup report; a wait that never returns ends boundedly with 125; the wrapper ends boundedly and reports truthfully when the execution process ignores TERM.
- Real Codex 0.162.1 against a local fake Responses endpoint (no credentials, temporary `CODEX_HOME`, no model calls): aborting during a long `sleep` by deadline, TERM, INT and HUP, once each, leaves neither `zsh -lc` nor `sleep` behind. `reap-fake-endpoint` is skipped when codex is not installed locally.
- The sha256 of `~/.codex/config.toml` was identical before and after testing.

Not yet verified:

- Linux hosts (the `/proc` process-listing path).
- Reclaiming in write mode (the `workspace-write` sandbox).
- The real cause of one S38 observation where `run_codex.py` did not exit within 60 seconds of TERM; it did not reproduce under free conditions and needs a real provider and paid calls to locate.
- Background processes Codex leaves after exiting normally, processes adopted before the freeze, and PID reuse between snapshot and signal remain outside the cleanup guarantee.

Other unverified items listed for v0.7.0 are unchanged.

## Updating

Run `claude plugin update delegate@delegate-marketplace`, then open a new session or run `/reload-plugins`. Upgrading from v0.7.0 needs no migration; workflows that decide success from exit status should treat 125 as failure.
