# v0.5.2: Codex reviews attach line numbers; README corrections

[简体中文](../../releases/v0.5.2.md) | English

This is a fix release after v0.5.1. Commands, options, and permission boundaries are unchanged, and upgrading from v0.5.1 needs no migration.

## Fix

- **Codex reviews attach line numbers**: file contents sent to the Codex backend previously had no line numbers, so the model had to count lines itself. In a real review the model returned findings with `line` set to null, they could not be located, and the whole review was marked `failed` (`review_incomplete`). Every content line now carries a 1-based line-number prefix, and the prompt says `findings.line` must be that file's line number. Snapshots and SHA-256 are still computed from the original files; the rule that any unlocated finding keeps a review incomplete is unchanged; the prefixes count toward the 1 MiB input cap.

## Documentation

The corrections below come from two real model reviews (one on the Claude backend, one on the Codex backend) and were checked against the code. Chinese and English are kept in sync.

- **Prerequisites and quick start**: `/delegate:review` requires a repository with at least one commit, while repositories without commits work only with `/delegate:run`; installing Codex and signing in with ChatGPT is marked as a Codex-backend-only step that Claude-review-only users can skip.
- **Troubleshooting**: the `native_authentication_environment_unverified` check now lists variable names only, so secret values are not printed; "No proposal after signing in" now explains that since v0.5.0 a proposal appears only on an explicit delegation request; a new row covers Claude backend diagnostics and next steps on non-macOS, without a GUI launchd domain, or when the kernel interface check fails; the meaning of Codex 0.160.0, 0.162.1, and the `@latest` install is spelled out.
- **`--model`**: the value is passed to the selected backend unchanged; the entry point first rejects invalid syntax, values from the other backend's model family, and Claude's `opusplan` (exit status 64), and only unknown values with valid syntax are left to the selected CLI. It previously said "invalid values fail in the CLI", which could make users mistake an entry-point rejection for a CLI or model-access problem.

## Verification and known limits

Free validation covers 166 Python tests (four more regression cases than v0.5.1), 53 shell assertions, and 19 evals; `claude plugin validate` passes for both the marketplace and the plugin.

After the line-number fix merged, a real Codex backend review of README.md, the four command files, and `spec/claude-review.md` was run from `main` source: all 6/6 files were reviewed, `execution_status=completed`, exit status 0, and the single finding carried a verifiable line number (README line 161, the `--model` description corrected in this release). Before the fix, the same scope was marked `failed` because findings lacked line numbers. The other unverified items listed for v0.5.0 are unchanged.

## Updating

Run `claude plugin update delegate@delegate-marketplace`, then open a new session or run `/reload-plugins`.
