# v0.7.0: Run timeouts keep progress, write mode leaves Codex user config alone

[简体中文](../../releases/v0.7.0.md) | English

A minor release after v0.6.0. A `/delegate:run` timeout now keeps progress and prints a result line, a resumable run can be resumed after a timeout, and the interface description moves to `1.2` (additions only). `--write` runs no longer make Codex write project trust to `~/.codex/config.toml`. Without the new options, command usage is unchanged; timeout output has changed, see "Upgrade notes" below.

## Upgrade notes

Consumers (scripts, plugins and session workflows that read delegate output or `interface.json`) should note three things:

1. **Timeouts now print a result line too.** Previously a run timeout printed only the Git acceptance block; it now prints the answer, metadata and `delegate: run_id=<id> status=timeout resumable=<true|false>`, and the exit code is still 124.
2. **Decide success by exit code 0 plus `status=done`.** A result line does not mean success; workflows that only check for a result line or a run_id must change. `statuses` is an open set: an unknown value must make the consumer stop or treat it as failure, never as completion. Consumers that only read `1.1` are unaffected: a timeout still exits 124 and can still be treated as failure.
3. **`--write` no longer writes trust records to `~/.codex/config.toml`.** Previously, the first `--write` run in a repository made Codex append `[projects."<repository path>"] trust_level = "trusted"`; now the repository is trusted for that run only, without persisting anything. Entries already written by earlier versions are not removed; delete them yourself if needed.

## Added

- **Keep progress on run timeout ([run-timeout](../SPEC-run-timeout.md))**: every run prompt ends with a time budget. The Codex main run gets the total deadline minus the wrap-up reserve (495 s at 540), and after the threshold (405 s at 540) the model should stop and start its answer with `TIME_UP:` followed by progress. After a resumable run is forcibly stopped, one more read-only round is resumed that only writes progress (at most 45 s). Plain runs, and wrap-up rounds that time out, fail, return nothing or have no session id, get a model-free fallback text; in write mode it lists the files changed during the run. Plain-run arguments (including `--ephemeral`) are unchanged.
- **Resume after timeout**: `--resume` accepts resumable runIds with `status=timeout`; plain-run timeouts cannot be resumed.
- **Interface description `1.2`, additions only**: `interface.json` appends `"timeout"` to `run.resume.statuses` and adds `run.timeout: {"status": "timeout", "exitCode": 124}`; the other fields are unchanged. Consumers check `>=1.2,<2.0` before resuming timed-out runs.

## Behavior changes

- **Write mode no longer writes Codex project trust ([write-trust](../SPEC-write-trust.md))**: before every write-mode run (plain, resumable and resume), delegate reads `~/.codex/config.toml` (read-only), and when it has no entry for this repository passes `-c projects={...}` so the repository is trusted for that run only. When an entry for this repository already exists (including `untrusted`), no argument is added. The trust key is the main repository path, matching Codex's own rule, so runs from a worktree subdirectory are covered. If the file cannot be read or is not UTF-8, the path contains a quote or backslash, or the repository layout is unusual, no argument is added, one line is printed on stderr, the exit code is unchanged, and the old behavior applies. Read-only runs and reviews keep their arguments.

## Fixes

- An occasional `PermissionError` (EPERM) from process-group cleanup in `run_codex.py` on macOS no longer interrupts cleanup.

## Validation and known limits

Free aggregate validation covers 247 Python cases (51 more than v0.6.0, 26 of them for run-timeout and 22 for write-trust), 53 shell and 19 eval, with 19 loop-registered Python regression suites (run-timeout and write-trust are new); `claude plugin validate` passes for both the marketplace and the plugin.

Paid real checks (Codex CLI 0.162.1; records in the 2026-10-26 section of the [verification records index](../verification/README.md), in Chinese):

- **run-timeout** ([Checkpoint 3](../../verification/2026-10-26-delegate-run-timeout-cp3.md), 12 model calls): under the real 540-second deadline the model stopped on its own at 412 s (threshold 405 s), 73 s before the main-run deadline; the full "forced stop → wrap-up round" path ran once; another model, `gpt-5.6-terra`, also stopped within budget; a write-mode resume did not repeat writes.
- **Wrap-up long tails are not rare**: 2 of 8 samples exceeded 45 s. In that case the hard deadline stops the wrap-up round and the fallback text is printed, so the total time stays within the limit, but no model-written progress is available. The constants are unchanged (specification revision R1).
- **write-trust** ([paid check](../../verification/2026-10-26-delegate-s36-write-trust-live.md), 1 run): while signed in, `--write` in a new repository wrote as usual, and the sha256 of `~/.codex/config.toml` was the same before and after. The [free real-machine check](../../verification/2026-10-26-delegate-s36-write-trust-check.md) covers the repository root, a subdirectory, a worktree subdirectory and an existing `untrusted` entry.

Not yet verified:

- Wrap-up round duration on large sessions (a hundred thousand tokens or more); the checks only reached about 32k tokens.
- Models other than `gpt-6.1-sol` and `gpt-5.6-terra`, and reasoning levels other than `none`.
- Resuming after a timeout interrupted a half-written file in write mode.
- The long-tail rate rests on only 8 samples and is indicative only.
- The paid write-trust check only covered a plain repository root; real write-mode resumable runs and resumes were not re-run with paid calls (their arguments are covered by stub tests).
- `projects` entries in system, managed or project-level configuration, and normalization of symlinked paths.

The other unverified items listed for v0.6.0 are unchanged.

## Updating

Run `claude plugin update delegate@delegate-marketplace`, then open a new session or run `/reload-plugins`. Upgrading from v0.6.0 needs no migration; workflows that read delegate output to decide success should be checked against the upgrade notes above.
