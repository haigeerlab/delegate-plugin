# delegate v0.4.0

[简体中文](../../releases/v0.4.0.md) | English

Published on 2026-10-08: [release page](https://github.com/haigeerlab/delegate-plugin/releases/tag/v0.4.0). This page records that version's changes; see [Unreleased](unreleased.md) for subsequent documentation revisions.

Delegate execution and investigation for settled approaches to Codex CLI. The main session receives the final answer while process logs remain local. This release focuses on execution lifecycle, authentication, Git verification, diagnostics, and usage help.

## Added

- `/delegate:help` provides commands, options, use cases, and troubleshooting.
- Wrapper `--help` / `-h` displays usage even without Codex installed.

## Fixes and improvements

- Clean up the execution process group on timeout, interruption, and normal exit. Timeout sends TERM, waits at most 2 seconds, then forcibly terminates remaining processes.
- Determine ChatGPT authentication from CLI status, supporting the CLI's own Codex home and keychain storage rather than inferring login from auth.json.
- Remove both API-key environment variables and select ChatGPT login and the OpenAI provider; unknown authentication remains rejected.
- Once write-mode execution has started, failures, timeouts, and empty answers still return a Git summary. Failure does not automatically roll back changes.
- doctor refreshes readiness every time. Cache is bound to CLI/home/plugin identity and written atomically; prompt hooks warm the cache then route sequentially.
- Failure log output is limited to 40 lines / 16KiB. Cleanup attempts to retain the latest 50 log/answer pairs.
- Aggregate validation includes every product suite; behavior evaluations explicitly load current source and accept only a complete first nonempty line as a verdict.
- Live tests follow CLI login status without requiring auth.json. Log-to-answer size ratio is observational, not a fixed 40× passing threshold.

## Changes when upgrading from 0.3.x

| Item | v0.4.0 contract |
|---|---|
| Authentication | ChatGPT login only; API-key and unknown states are rejected |
| Execution deadline | Default and maximum 540 seconds; the environment variable can shorten it, larger values are capped, invalid/non-positive values use the default |
| Working directory | Every invocation requires a Git working tree; no non-Git bypass |
| Command names | Use `/delegate:delegate`, `/delegate:doctor`, and `/delegate:help` |
| Write-mode failure | Inspect Git evidence on stderr and verify changes manually; failure does not mean no files changed |
| doctor | Refreshes temporary cache; exit 0 means diagnostics completed, assess the text's issue count |
| Log compression ratio | Size ratio is observational; no fixed 40× benefit is promised |

This release uses version 0.4.0 because tighter authentication and timeout limits affect users visibly and should not be hidden in an ordinary patch.

## Installation and upgrade

Install from GitHub:

```bash
claude plugin marketplace add haigeerlab/delegate-plugin
claude plugin install delegate@delegate-marketplace
```

Alternatively, download source from the [v0.4.0 release page](https://github.com/haigeerlab/delegate-plugin/releases/tag/v0.4.0), extract it, and enter the repository directory:

```bash
claude plugin marketplace add "$PWD"
claude plugin install delegate@delegate-marketplace
```

Users installed from the remote marketplace can update manually, then start a new session:

```bash
claude plugin update delegate@delegate-marketplace
```

Check `codex login status` in your terminal for ChatGPT authentication, then run `/delegate:doctor` inside Claude Code in the target Git project and try a small read-only task.

Editing another local source checkout does not update remote installation cache. The current host can load relative-path plugins from a local-path marketplace directly from source, applying edits in a new session or through `/reload-plugins`. Remote host auto-update is configured by users or administrators. See [README](../../../README.en.md#updates-and-uninstalling) and the [official documentation](https://code.claude.com/docs/en/plugin-marketplaces) for source and update methods.

## Verification scope

- Free validation: 52 original assertions and 17 Python regressions, plus manifest, syntax, and evaluator checks passed.
- Real-model samples: read-only inspection, authorized writes with Git evidence, two Claude behavior evaluations, and help-command loading passed.
- Headless evaluation does not guarantee proposals on every interactive turn. Local login status does not guarantee remote connectivity, quota, or model access.

## Rollback and guarantee boundaries

If a regression affects use, stop delegating, retain current Git changes and logs, and load source from a known version with `--plugin-dir` for diagnosis. Reverting the plugin does not automatically undo files already written by a model. Older versions also restore their older authentication and lifecycle behavior. Users deliberately manage installation cache changes.

Confirmation and restrictions against committing/pushing are model instructions; the wrapper has no authorization lock that cannot be bypassed. Real sandbox permissions depend on Codex and the host. Descendants leaving the process group are not guaranteed to be reclaimed. A Git summary does not prove code correctness, and log-count limits do not bound individual file sizes.
