# v0.9.0: Review reports add a recomputable patch fingerprint (interface 1.4)

[简体中文](../../releases/v0.9.0.md) | English

This is the minor release after v0.8.6. **From this release, review reports carry a patch fingerprint that does not depend on local git configuration, so it can be recomputed on another machine such as GitHub Actions to bind a review conclusion to a specific patch.** The interface description moves from `1.3` to `1.4` and only adds fields; the report `schema_version` stays `1`, command arguments and exit codes are unchanged, and no migration is needed.

This comes from ledger item S98: autopilot needs to check on Actions that "this review covered exactly this PR's changes", but the existing `scope.diff_sha256` is computed over diff text, which depends on the repository's `.git/config` (`diff.algorithm`, `diff.noprefix`, `diff.context`, `core.quotepath`, `core.abbrev`), `.gitattributes` and the git version, so it does not match on another machine. The user approved the specification and plan on 11-20. The three items previously announced for 1.4, such as `run.restore`, have not been started and move to the next minor version.

## Changes

- **New `scope.fingerprint`**: `{"algorithm": "blob-pairs-v1", "sha256": …, "paths": […]}`. It is set only for a baseline between two commits (`commits`); the `staged`, `unstaged` and `working-tree` baselines give `null`. `paths` equals the set of reviewed files used to build the diff; files removed by `exclude` are not included.
- **Algorithm `blob-pairs-v1`**: the first line is the header `delegate-blob-pairs-v1`; each reviewed path gets one line with the path, `\0`, and the mode and object id of both sides; lines are ordered by the UTF-8 bytes of the path; a side that is missing or a directory is written as `000000` with an all-zero id; the sha256 is taken over the whole text. Only facts from the two commit trees are used, never diff text. The full definition, fixed test vectors and a recomputation reference are in the [review-fingerprint specification](../SPEC-review-fingerprint.md).
- **`interface.json` moves to 1.4**: `review.report` gains `fingerprint`, naming the field, the algorithm and the baselines it applies to; everything else is unchanged.
- **New fixed diagnostic `fingerprint_inputs_inconsistent`** (exit 127): reported when the file entries obtained do not match the reviewed files; no partial fingerprint is emitted.
- **`scope.diff_sha256` is unchanged**: still the sha256 of the diff text, valid only on the local machine.

## How consumers should read it

A matching fingerprint only says the review covered the patch you computed; **it does not mean the change may be merged**. Also compare `paths` with the files the PR actually changes. Treat an unknown `algorithm` as not recomputable. When recomputing on Actions, a shallow clone must still be able to reach the `from` commit.

## Validation and known limitations

Every behavior got a test that was confirmed to fail before the implementation. A new `test-review-fingerprint.py` (byte-for-byte fixed vector, empty set, UTF-8 byte order, 64-character ids); four new tests in `test-review-context.py`: six change shapes (added, deleted, modified, mode-only, file to symlink, file to directory) match an independent `git ls-tree` recomputation; under five diff settings plus a `-diff` attribute, `diff_sha256` changes while the fingerprint does not; the three uncommitted baselines give `null`; inconsistent entries report the fixed diagnostic. `test-review-result.py` and `test-interface.py` cover the report field and interface 1.4. After the change, free validation covers 354 Python, 53 shell and 19 eval checks, with 27 loop-registered Python regression suites; `claude plugin validate` passes for both the marketplace and the plugin.

**Consistency across git versions has not been tested**; it rests on the algorithm using only tree object facts. The field in a real model review report has not been checked separately (paid, not required by the specification). The other unverified items listed in v0.8.0 are unchanged.
