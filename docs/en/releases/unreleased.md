## Reviews no longer include untracked files ignored globally

`/delegate:review --changes working-tree --include-untracked` treated files ignored only by the global excludes file (git's default `~/.config/git/ignore` or `$XDG_CONFIG_HOME/git/ignore`) as untracked changes and sent them to the reviewer; in practice the permission allowlist in a local `.claude/settings.local.json` reached the review input. The environment delegate prepares for git subprocesses had no `HOME` or `XDG_CONFIG_HOME`, so git could not find the default global excludes file. Only these two variables are now passed through; the isolation from global git configuration, hooks, fsmonitor and attribute files is unchanged, and the path-less `--dry-run` preview is fixed the same way.

## Impact

- Only working-tree reviews with `--include-untracked`, and path-less review previews, are affected: files ignored globally no longer enter the review scope. Repository `.gitignore` behaviour is unchanged.
- Known limitation: an excludes file set with `core.excludesFile` in the global git configuration still does not apply (global configuration stays isolated); only git's default location is honoured.
- Report fields, exit codes and the interface version (1.8) are unchanged; the only code change is in `review_context.git()`.

## Validation and known limitations

New regression tests were seen to fail before the fix: the snapshot layer covers the default and XDG paths and uses a global `diff.noprefix` to confirm global configuration still has no effect; the CLI layer checks the `--dry-run` preview list. The relevant suites were rerun after merging the fix branch with v0.13.0. Reviews made earlier with `--include-untracked` may already have sent globally ignored files to the reviewer; this release does not change that.
