## Pre-granted write authorization accepts autopilot-hub

The accepted consumers of `run --write --authorized-by` grow from module-crew alone to module-crew and autopilot-hub (from ecosystem-lead #23450; wording approved by the user on 2026-11-27). hub's four conditions: the user's words from switching the repository onto the automatic path are recorded by hub as the authorization file; the case comes from an approved module's regression test document; each case gets a fresh throwaway clone and one plain run, with no resuming; the `authorization` field is kept unchanged in the result and in hub's verification report. module-crew's four conditions are unchanged. delegate still does not read the authorization file; code, options and the interface version are unchanged.

## Impact

Discipline text only: `references/run.md`, the pointer sentences in `commands/run.md` and the `delegate-routing` skill, the Chinese and English plugin READMEs, the Chinese and English run-check specs, and the "provided to autopilot-hub" line in the shared "responsibility boundary" section. No scripts, tests or `interface.json` changed.

## Validation and known limitations

`validate.sh --quick`, the shared-section consistency check and `git diff --check` pass. Whether conditions 2 and 3 hold is hub's responsibility; delegate can only check that the authorization file is usable, that the whole chain uses the same file and that the repository matches. This is discipline at the command-instruction level, not a technical lock.
