# v0.8.4: A dedicated diagnostic for reviewing a repository without commits

[简体中文](../../releases/v0.8.4.md) | English

A patch release after v0.8.3 that changes one diagnostic: **`/delegate:review` in a repository with no commits yet now reports `repository_has_no_commits` instead of the generic `git_probe_failed`**. The interface description stays `1.3`; command options, exit statuses and the rest of the report are unchanged, and no migration is needed.

It follows the ecosystem lead's test on 11-04 (ledger item S75, point 9): reviewing a new repository with no commits only produced `git_probe_failed`, which did not say why. v0.8.3 explained it in troubleshooting first; this release makes the diagnostic itself say so.

## Fixes

- **New diagnostic `repository_has_no_commits`**: reported when reading HEAD fails and the repository has no refs at all. The exit status stays 127, the report's `execution_status` stays `conditions_missing`, `--dry-run` behaves the same, and no model is started; it applies to both fixed-commit and working-tree scopes.
- **Other Git query failures are unchanged**: when commits exist, cases such as `--base`/`--head` naming a missing commit still report `git_probe_failed`.
- **Documentation**: the troubleshooting table in both root READMEs is split into two rows, one per diagnostic; `/delegate:help` is updated.

## Compatibility

`diagnostics` is not a stable field. In this case the report's stable field `unreviewed[].reason` also changes from `git_probe_failed` to `repository_has_no_commits`; this field never defined a set of values and no known consumer branches on it, so the interface version is not bumped. Scripts that recognise "no commits" by `git_probe_failed` need to accept the new code.

## Validation and known limitations

The regression test came first: a repository without commits asserts the new code under both fixed-commit and working-tree scopes, and it was confirmed to fail before the fix; another test keeps a missing commit in existing history reporting `git_probe_failed`. After the fix, free validation covers 330 Python, 53 shell and 19 eval checks; `claude plugin validate` passes for both the marketplace and the plugin. This release makes no paid calls.

When the current branch has no commits but the repository has other refs (for example a branch made with `git switch --orphan`), `git_probe_failed` is still reported. The other unverified items listed in v0.8.0 are unchanged.

## Update

Run `claude plugin update delegate@delegate-marketplace`, then open a new session or run `/reload-plugins`. Upgrading from v0.8.3 needs no migration.
