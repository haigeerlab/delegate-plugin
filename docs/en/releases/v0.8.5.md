# v0.8.5: Fix every Codex review failing, and name two failure causes

[简体中文](../../releases/v0.8.5.md) | English

A patch release after v0.8.4. **In v0.8.4 and earlier, every `/delegate:review` from Claude Code to Codex fails; this release fixes it, so please upgrade soon.** The interface description stays `1.3`; command options and exit statuses are unchanged, and no migration is needed.

It follows a user report on 11-18 that "the review plugin seems broken"; the ecosystem lead reproduced two problems (ledger items S87 and S88).

## Fix (S87)

- **Review result schema rejected**: in `review_result.py`, `schema_version` had only `const: 1` and no `type`. OpenAI strict structured outputs require every node to declare a type, so the whole schema was rejected (400 `invalid_json_schema`) and every Codex review reported `execution_status=failed` with `codex_result_invalid`. It now has `type: integer`. A new regression test walks the whole schema for strict-mode rules (every node typed; objects forbid additional properties and require every property) and was confirmed to fail before the fix. The schema had not changed for a long time and real reviews had succeeded before, so the service presumably tightened validation later; this is not confirmed.
- **Visible failure causes**: when the Codex event stream contains an `error` or `turn.failed` event, `codex_turn_failed` is reported besides `codex_result_invalid`, plus `codex_output_schema_rejected` when the schema was rejected.

## Diagnostic improvement (S88)

- A Claude Code review launched from Codex failed with `claude_api_server_error`, which looks like a service outage; the real cause was a local network (Cloudflare WARP) decrypting TLS with a root certificate that exists only in the system keychain, which the sandboxed claude under srt does not trust. This case now also reports `claude_api_tls_untrusted`, and troubleshooting explains the fix: exclude the Anthropic domains from decryption in that network's admin settings, or use `--backend codex`.
- This release **does not change the sandbox's certificate trust or network boundary**. Letting the sandbox trust a certificate the user names explicitly needs a specification change and separate approval, and is not in this release. `/delegate:doctor` makes no network requests and still cannot detect this.

## Confidentiality

The new diagnostics match fixed markers only; raw error text never enters the report or the private log, in line with the existing contract (the specification keeps only safe error codes in logs).

## Validation and known limitations

Three regression tests were written first and confirmed to fail before the fixes. After the fixes, free validation covers 333 Python, 53 shell and 19 eval checks; `claude plugin validate` passes for both the marketplace and the plugin. This release makes no paid calls; the ecosystem lead ran a real Codex review with the same schema change in a temporary copy (completed, with findings), and this repository made no separate real call. The other unverified items listed in v0.8.0 are unchanged.

## Update

- Claude Code: run `claude plugin update delegate@delegate-marketplace`, then open a new session or run `/reload-plugins`.
- Codex: if `[marketplaces.delegate-marketplace]` in `~/.codex/config.toml` pins `ref` to an older tag, change it to `"v0.8.5"`, then reinstall or update the plugin the Codex way and reopen the session.
