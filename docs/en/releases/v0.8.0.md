# v0.8.0: Hand a whole module to Codex

[简体中文](../../releases/v0.8.0.md) | English

A minor release after v0.7.1. `/delegate:run` gains a result file, continuing with the next task in the same session, a long-task deadline, a post-run check, a pre-granted write authorization and a rules section; the interface description moves to `1.3` (additive only). Without the new options, command usage and the 540-second deadline are unchanged; stdout and process logs change, see "Upgrade notes" below.

## Upgrade notes

Consumers that read delegate output, process logs or `interface.json` (scripts, plugins, session workflows) should note four things:

1. **One more line before the result line.** The result line format is unchanged and it is still the last line of stdout; it is now immediately preceded by `delegate: result=<path>`. When there is no result line (failure, interruption, unreaped, empty answer), this line goes to stderr instead; when the result file cannot be written, the line is not printed and stderr shows `delegate: 结果文件写入失败。` (result file write failed). Workflows that take the result line as "the last line" are unaffected; workflows that treat "all output before the last line" as the answer or question text will now include this line and need to drop it. module-crew's offload is known to take the question text this way on `needs-input`; that revision is handled separately.
2. **Process logs are now two files.** `<runId>.events.jsonl` is the event stream of Codex run with `--json`, and `<runId>.log` is stderr; the log tail printed to stderr on failure changes accordingly and is followed by the most recent events. Scripts that read log text need adjusting; logs are not part of the interface, so read the result file for structured results.
3. **Decide success by exit status first.** Exit status 0 first, then `status=done`. The result file `status` adds `unmarked` (only with `--strict`) and, where there is no result line, `failed`, `interrupted`, `unreaped` and `empty`; stop or treat unknown values as failure.
4. **State files are kept for 14 days.** State, claim and result files of `--resumable` chains are no longer pruned with the latest 50 log groups; they are kept for 14 days. Process logs are still pruned to the latest 50 groups.

## Added

- **Result file ([run-result](../SPEC-run-result.md))**: every run that started Codex writes a JSON result file with the session ID, status, first-line end markers, the commands run and their exit codes, files changed in write mode, and token usage for this run and for the whole session (`usage.run` is the difference of session totals). New `--strict`: a missing first-line end marker gives `unmarked`, exit 1.
- **Continue ([run-continue](../SPEC-run-continue.md))**: new `--continue <runId>` carries on with the next task in the same Codex session after a `done` round of a `--resumable` chain. Read-only/write mode and repository must match the original run, and each round can be continued only once; the result file records `kind`, `parent` and `chainRoot`.
- **Long tasks ([run-longrun](../SPEC-run-longrun.md))**: new `--timeout <seconds>` widens the deadline to 541–7200 seconds, with the time budget and wrap-up scaled by the run-timeout formulas; the default is still 540 seconds. Above the host's foreground limit the caller must use background mode; delegate does not manage background processes. Abort cleanup is the one from v0.7.1.
- **Post-run check ([run-check](../SPEC-run-check.md))**: new `--check "<command>"` runs a check command in the working tree as an argument list without a shell after a run ends `done`; the outcome (passed / failed / timeout / cannot run, exit code, output tail) goes into the result file and one line is printed before the Git acceptance block. Commands containing shell operators are refused, with the same rule as module-crew S30.
- **Pre-granted write authorization (run-check)**: new `--authorized-by <file>` records the path, sha256 and size of the write-authorization file; a whole chain must use the same file and a different sha256 is refused. delegate does not read the authorization content; it only checks the file and the repository. `run.write` stays `"explicit"`; the `delegate-routing` write rule gains the `--authorized-by` exception.
- **Rules section ([run-rules](../SPEC-run-rules.md))**: new `--rules-file <file>` puts rules meant only for this delegation verbatim after the preamble; Codex still reads AGENTS.md by itself. The result file records only the path, sha256 and size of the rules file, not its text.
- **Interface description `1.3`, additive only**: `interface.json` gains seven capability markers under `run` — `result`, `usage`, `continue`, `longRun`, `check`, `writeAuthorization`, `rules` — and no existing field is removed or changed. Consumers enable each with `>=1.3,<2.0` and the field present.
- **Usage notes**: the 1.3 usage and authorization rules of `/delegate:run` are in the plugin's `references/run.md`; the command text only adds a "read this first" pointer.

## Verification and known limits

Free aggregate validation covers 328 Python cases (75 more than v0.7.1: run-result 31, run-check 17, run-continue 12, run-longrun 5, run-rules 5, interface description 5), 53 shell and 19 eval cases, and 25 loop-registered Python regression suites (adding the five above; their registration was missed in the merge and is added in this release); `claude plugin validate` passes for the marketplace and the plugin.

Paid live tests (Codex CLI 0.162.1, the local default model; records under the 2026-10-27 section of the [verification index](../verification/README.md), in Chinese):

- **S38 preliminary probe** ([record](../../verification/2026-10-27-delegate-s38-probe.md), 18 calls): the session ID, commands with exit codes, and cumulative usage in the event stream can feed the result file; the same session can take a new task; a long-deadline run ends normally (656 seconds, not through `--timeout` at the time).
- **Merged live test** ([record](../../verification/2026-10-27-delegate-1.3-merged-live.md), 4 calls): result-file fields match the real events item by item; the `usage.run` difference is correct; `--continue` carries on in the same session; `--authorized-by` is checked along the chain; `--check` runs in the real working tree; with `--strict` the first-line end marker won over a contrary AGENTS.md instruction; a `--write` mismatch with the original run is refused without calling Codex.
- `~/.codex/config.toml` had the same sha256 before and after the merged live test.

Not yet verified:

- **A real run longer than 540 seconds under `--timeout` is not yet verified** (the merged live run took 500 seconds), nor are wrap-up and cleanup when such a run is aborted; the deadline conversion is covered by stub tests. Consumers that rely on long tasks (such as module-crew's module offload) should add this live test before using it.
- Without `--strict`, if AGENTS.md asks for another first-line format, the answer may not start with an end marker and the result is still `done`. This is a documented limit; use `--strict` when a reliable marker is needed.
- Whether `--strict` wins over AGENTS.md on other models and reasoning efforts (tested once on the local default model).
- The timeout, cannot-run and unreaped outcomes of `--check` are covered only by stub tests.
- Context usage, compaction and quota are not in the result file: they exist only in Codex's own session files, which 1.3 does not read.

Other unverified items listed for v0.7.1 are unchanged.

## Updating

Run `claude plugin update delegate@delegate-marketplace`, then open a new session or run `/reload-plugins`. No migration is needed from v0.7.1; workflows that read fixed stdout line numbers or process-log text should check the upgrade notes above.
