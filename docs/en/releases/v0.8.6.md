# v0.8.6: The Claude review backend trusts explicitly trusted system certificates

[简体中文](../../releases/v0.8.6.md) | English

A patch release after v0.8.5. **On networks that decrypt TLS, such as Cloudflare WARP or a corporate proxy, `/delegate:review` from Codex to Claude Code can connect from this release on.** The interface description stays `1.3`; command options, exit statuses and the report structure are unchanged, and no migration is needed.

It follows ledger item S88: this Mac has run Cloudflare WARP since 11-02, which decrypts TLS with a root certificate trusted only in the system keychain; claude inside the srt sandbox could not read it and reviews failed. The user declined to change the network software's exclusion settings, chose "C, automatic export", and approved the specification on 11-18 ("批准，开始实现", i.e. "approved, start implementing").

## Changes

- **Explicitly trusted certificates are added automatically**: before starting the sandbox for each Claude backend review, delegate exports the admin and user trust settings read-only with `/usr/bin/security`, selects certificates trusted unconditionally or for `sslServer`/`basicX509` (denied ones and those trusted only for other uses are skipped), fetches them by SHA-1 from the system and login keychains and **recomputes each hash**. Selected certificates go into a read-only file for this run (directory 0700, file 0400, at most 64 certificates and 1 MiB), added to the sandbox's readable paths (not writable) and appended for the sandboxed claude through `NODE_EXTRA_CA_CERTS`; claude's bundled public roots still apply. The file is deleted with the run, and the review tools cannot read it.
- **Failure does not stop the review**: if the export fails, no certificate is added, the review proceeds, and the report gains the non-fatal diagnostic `system_trust_export_unavailable`.
- **doctor**: `/delegate:doctor --backend claude-code` shows how many certificates were exported, or the export failure code, without certificate names, hashes or paths; it still makes no network requests.

## Boundaries

srt's `enableWeakerNetworkIsolation` stays off (opening trustd, which srt itself flags as an exfiltration vector); no private keys are read and the keychain and trust settings are never written; the trust store is not replaced; the caller's `NODE_EXTRA_CA_CERTS` is not inherited; the network still allows only the three Anthropic endpoints; the Codex backend and `/delegate:run` are unaffected. The exact contract is in the [claude-review specification, "Sandbox certificate trust"](../SPEC-claude-review.md).

## Validation and known limitations

Tests came first and were confirmed to fail before the implementation: a new `test-review-trust.py` (selection rules, hash-matched fetching, the read-only file, every failure) and four sandbox wiring tests in `test-review-native.py` (readable but not writable, hidden from the review tools, the caller's variable not inherited, failure as a non-fatal diagnostic, doctor showing only the count). All free parts use a fake `security` command, never reading the real keychain or calling a model. After the change, free validation covers 343 Python, 53 shell and 19 eval checks, with 26 loop-registered Python regression suites; `claude plugin validate` passes for both the marketplace and the plugin.

A manual export with the real `security` on this Mac (read-only, no model) produced 3 certificates with file mode 0400. **A real Claude backend review with WARP on (specification CR-14) has not been run**; it uses Claude quota and needs separate user authorization, so until then a successful review under WARP remains unverified. Selected certificates are not checked for being CA certificates; system trust settings decide. The other unverified items listed in v0.8.0 are unchanged.

## Update

- Claude Code: run `claude plugin update delegate@delegate-marketplace`, then open a new session or run `/reload-plugins`.
- Codex: change `ref` in `[marketplaces.delegate-marketplace]` of `~/.codex/config.toml` to `"v0.8.6"`, run `codex plugin marketplace upgrade delegate-marketplace` and `codex plugin add delegate@delegate-marketplace`, then reopen the session.
