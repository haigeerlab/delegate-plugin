# v0.8.6：Claude 审查后端信任系统明确信任的证书

简体中文 | [English](../en/releases/v0.8.6.md)

这是 v0.8.5 之后的补丁版。**在 Cloudflare WARP、公司代理等会解密 TLS 的网络下，Codex 调 Claude Code 的 `/delegate:review` 从本版起可以正常连接。** 接口说明仍为 `1.3`，命令参数、退出码和报告结构不变；不需要迁移。

起因是总账 S88：本机从 11-02 起装了 Cloudflare WARP，它解密 TLS，根证书只在系统钥匙串里被信任；srt 沙箱里的 claude 读不到，审查失败。用户表示不改网络软件的免检设置，选定方案「C 自动导出」，并于 11-18 批准规格（原话「批准，开始实现」）。

## 变化

- **自动追加明确信任的证书**：每次 Claude 后端审查启动沙箱前，delegate 用 `/usr/bin/security` 只读导出管理员域和用户域的信任设置，挑出无条件信任或对 `sslServer`、`basicX509` 设为信任的证书（被设为拒绝的、只对其他用途信任的都不选），再按 SHA-1 从系统钥匙串和登录钥匙串取回证书并**自行重算哈希核对**。入选证书写成本次运行专用的只读文件（目录 0700、文件 0400，最多 64 张、1 MiB），加入沙箱的可读路径（不可写），通过 `NODE_EXTRA_CA_CERTS` 追加给沙箱里的 claude；claude 自带的公共根证书照旧生效。文件随本次运行删除，审查工具层也读不到它。
- **失败不影响运行**：导出失败时不追加任何证书，审查照常进行，报告加非致命诊断 `system_trust_export_unavailable`。
- **doctor**：`/delegate:doctor --backend claude-code` 显示导出了几张证书，或导出失败的诊断码；不显示证书名称、哈希或路径，仍不联网。

## 边界

不打开 srt 的 `enableWeakerNetworkIsolation`（放开 trustd，srt 官方标明有外泄风险）；不读取私钥、不写钥匙串或信任设置；不替换信任库；不继承调用方环境里的 `NODE_EXTRA_CA_CERTS`；网络仍只放行三个 Anthropic 端点；Codex 后端与 `/delegate:run` 不受影响。精确合同见 [claude-review 规格「沙箱证书信任」](../../spec/claude-review.md)。

## 验证与已知限制

先写测试并确认实现前失败：新增 `test-review-trust.py`（选证规则、按哈希取证、只读文件、各类失败）与 `test-review-native.py` 的沙箱接入四条（可读不可写、工具层读不到、不继承调用方变量、失败为非致命诊断、doctor 只显示张数）。免费部分全部使用假 `security` 命令，不读真实钥匙串、不调用模型。修复后免费总验证为 343 项 Python、53 项 shell 和 19 项 eval，循环注册的 Python 回归套增至 26 个；`claude plugin validate` 对 marketplace 和插件都通过。

另在本机真实 `security` 上手动导出一次（只读、不调用模型）：导出 3 张证书、文件权限 0400。**开着 WARP 跑真实 Claude 后端审查（规格 CR-14）尚未做**，需要使用 Claude 额度，另经用户授权；在那之前，WARP 下能否审查成功仍属未验证。不检查入选证书是否为 CA 证书，以系统信任设置为准。v0.8.0 列出的其余未验证项不变。

## 更新

- Claude Code：运行 `claude plugin update delegate@delegate-marketplace`，然后打开新会话或执行 `/reload-plugins`。
- Codex：把 `~/.codex/config.toml` 里 `[marketplaces.delegate-marketplace]` 的 `ref` 改成 `"v0.8.6"`，再运行 `codex plugin marketplace upgrade delegate-marketplace` 和 `codex plugin add delegate@delegate-marketplace`，然后重开会话。
