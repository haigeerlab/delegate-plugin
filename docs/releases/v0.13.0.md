# v0.13.0：按后端配置默认模型（接口 1.8）

简体中文 | [English](../en/releases/v0.13.0.md)

## 按后端配置默认模型

派审查或执行时不点名模型，就用 `~/.config/delegate/config.json`（或 `$XDG_CONFIG_HOME/delegate/config.json`）里按后端写好的默认值，例如 Codex 用 `gpt-6.2-sol`、Claude Code 用 `claude-opus-5-5`；有特殊需求时照旧点名。合同见 [default-model 规格](../../spec/default-model.md)。

- 优先级：这次点名 > 配置 > 宿主默认，模型和推理档分别取值；`--backend auto` 选中哪家用哪家的默认值；`--resume`、`--continue` 沿用原会话。从 Codex 里调 Claude Code 审查读同一份文件。
- 文件格式 `delegate.config/v1`，只认 `schema`、`defaults` 与每个后端的 `model`（Codex 另有 `effort`）；多出来的键、不合法的模型名或推理档都算错误。
- 审查报告新增稳定字段 `model_source`，结果文件新增 `modelSource`、`effortSource`，run 输出的模型一行注明来源；`/delegate:doctor` 最前面列出当前生效的默认值。

## 影响面

- 接口说明从 `1.7` 升到 `1.8`，只增字段；报告 `schema_version` 与结果文件 `schema` 仍为 `1`。各插件主线没有读 `model`、`effort` 或 `requested_model` 的调用方（ecosystem-lead 2026-11-26 在 agent-relay 消息 #23282 中按各仓主线 `git grep` 核对）。
- 没有配置文件时行为与 v0.12.6 相同。
- **配置文件存在但有错时，所有 review／run 退出 64**，stderr 为一行 `delegate: invalid config <路径>: <原因码>[ at <字段>]`；module-crew、autopilot 等调用方可原样转给用户。`/delegate:doctor` 此时退出 1。
- 诊断字段 `requested_model` 的含义改为 delegate 实际传给后端的模型（点名或配置；宿主默认为 `null`）。
- 直接调用旧入口 `codex-exec.sh` 不读配置。

## 验证与已知限制

新行为先写测试并确认实现前失败；入口统一读配置之后补的回归（run 侧配置错误、十种错误经两个入口、`--reviewers` 不变）实现已在、直接通过，其中两项用临时变异确认能拦住回归。取值穷举、十种配置错误、路径规则、审查与执行端到端、续跑、doctor、接口形状都用桩后端和临时目录覆盖。回归套件运行时给每个套件一个空的私有 `XDG_CONFIG_HOME`，不会读到本机真实配置。未用真实 Codex／Claude 实跑；Claude 路径在进程内替换审查函数，只核对传入的模型，真实 CLI 收到 `--model` 的那一步沿用原有代码。

本次发版准备实测：免费总验证 587 项 Python，循环注册的 Python 回归套 32 个。
