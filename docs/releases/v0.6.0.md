# v0.6.0：可续跑委托，Codex 调用固定不经审批

简体中文 | [English](../en/releases/v0.6.0.md)

这是 v0.5.3 之后的次版本。新增可续跑委托，接口说明升到 `1.1`；所有让 Codex 执行任务的调用改为固定审批方式，写模式下的行为因此有变化，见下文“行为变化”。不加新参数时，命令用法与报告格式不变。

## 新增

- **可续跑委托（[run-resume](../../spec/run-resume.md)）**：`/delegate:run --resumable` 让 Codex 先做不受待定决策影响的部分，碰到需要用户拍板的事就停下，返回 `needs-input`；`/delegate:run --resume <runId> -- "<答复>"` 带着用户答复续跑原 Codex 会话。默认不开启。每次成功返回的末行给出 run_id 与结束状态（`done` 或 `needs-input`）。
- **接口说明 `1.1`**：`interface.json` 只新增 `run.resume`（`optIn: "--resumable"`、`option: "--resume"`、后端 `codex`、状态 `done` / `needs-input`）；`review.command`、`doctor.command` 和其余字段不变。使用方按 `>=1.1,<2.0` 判断能否续跑；读到 `1.0` 或没有该字段时按原做法处理，不续跑。

## 行为变化

- **所有 run 与 Codex 审查固定 `approval_policy="never"`**：普通 run（只读与写入）、可续跑 run、续跑、Codex 后端审查，一律传 `-c approval_policy="never"`，不再沿用本机 Codex 配置的审批方式。只做探测、不调用模型的命令（`codex --version`、`codex login status`、`codex features list`）不受影响。
- **写模式下越出沙箱的命令会被拒**：以前本机若配置了 `on-request` 等审批方式，越出沙箱的命令可能经审批放行；现在不再请求审批，直接拒绝。需要越出沙箱的写入任务（例如依赖额外放行规则的命令）可能因此失败。
- 这项改动消除的是“只读路径越出沙箱的请求被代批放行”的风险。开发中实测过：可续跑的只读续跑在本机 `approval_policy="on-request"` 加 `approvals_reviewer="guardian_subagent"` 下写出了文件；改为 `never` 后同一任务不再写出。
- 关于 v0.5.3 及更早版本：只读 run 以只读沙箱启动，但没有固定审批方式。本机配置了能代为批准的审批方式（如 `on-request` 加 `guardian_subagent`）时，越出沙箱的请求在技术上可能被放行，是否写入主要靠提示词里的“不要修改文件”约束。用 v0.5.3 只读 run 实测时没有写出文件，因为模型按提示词没有尝试写入。v0.5.3 的 Codex 审查不读取用户配置、也没有执行命令的工具，不受影响。在这类配置下用只读 run 的，建议升级。

## 验证与已知限制

免费总验证覆盖 196 项 Python（比 v0.5.3 多 23 项，其中续跑 20 项）、53 项 shell 和 19 项 eval，17 个循环注册的 Python 回归套；`claude plugin validate` 对 marketplace 和插件都通过。

付费真实实测（Codex CLI 0.162.1，记录见 [run-resume 任务记录](../../tasks/run-resume/todo.md)）：
- 可续跑只读 run 先返回 `needs-input`，续跑后上下文接上并返回 `done`，没有写出文件。
- 当前源码的普通只读 run 在同样提示词下没有写出文件。

尚未验证：
- `approval_policy="never"` 时沙箱对写入命令的技术拦截没有被直接考验到：上述实测里都是模型自己没有尝试写入，没有出现写入命令被操作系统拒绝的记录。
- 写模式 run 在 `never` 下的真实行为（例如依赖前缀放行规则的 `git commit`）没有实测。
- Codex 审查在本机配置下的事件流没有保存，无法逐条核对。

v0.5.0 列出的其余未验证项不变。

运行 `claude plugin update delegate@delegate-marketplace`，然后打开新会话或执行 `/reload-plugins`。从 v0.5.3 升级不需要迁移；使用写模式 run 的流程，请留意上面的行为变化。
