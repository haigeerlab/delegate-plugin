# v0.8.5：修复 Codex 审查全部失败，并说清两类失败原因

简体中文 | [English](../en/releases/v0.8.5.md)

这是 v0.8.4 之后的补丁版。**v0.8.4 及以前，Claude Code 调 Codex 的 `/delegate:review` 会全部失败，本版修复，请尽快升级。** 接口说明仍为 `1.3`，命令参数和退出码不变；不需要迁移。

起因是 11-18 用户反馈「审查的插件好像不能用了」，生态总负责人复现出两个问题（总账 S87、S88）。

## 修复（S87）

- **审查结果 schema 被拒**：`review_result.py` 里 `schema_version` 只写了 `const: 1`，没写 `type`。OpenAI 结构化输出的严格模式要求每个节点都声明类型，于是整份 schema 被拒（400 `invalid_json_schema`），Codex 审查一律报 `execution_status=failed`、`codex_result_invalid`。现已补上 `type: integer`。新增回归测试逐个节点检查整份 schema 是否满足严格模式（每个节点有 `type`，对象禁止额外字段且 `required` 列全），修复前确认失败。这个 schema 很久没改过，此前也有真实审查成功，推测是服务端后来收紧了校验，未能证实。
- **失败原因看得见**：Codex 事件流里有 `error` 或 `turn.failed` 事件时，`codex_result_invalid` 之外另报 `codex_turn_failed`；错误是 schema 被拒时再报 `codex_output_schema_rejected`。

## 诊断改进（S88）

- Codex 调 Claude Code 审查失败，表面是 `claude_api_server_error`，像对方服务故障；实际原因是本机网络（Cloudflare WARP）解密 TLS，它的根证书只在系统钥匙串里，srt 沙箱里的 claude 不信任它。现在这种情况另报 `claude_api_tls_untrusted`，故障排查给出办法：在该网络的管理设置里把 Anthropic 域名设为不解密，或改用 `--backend codex`。
- 本版**不改沙箱的证书信任和网络边界**。让沙箱信任用户显式指定的证书需要先改规格、另行批准，不在本版。`/delegate:doctor` 不联网，仍查不出这类问题。

## 保密

新诊断码都只匹配固定标记，错误原文不进入报告或私有日志，与原有合同一致（规格要求日志只保留安全错误码）。

## 验证与已知限制

先写 3 条回归测试并确认修复前失败，再修复。修复后免费总验证为 333 项 Python、53 项 shell 和 19 项 eval；`claude plugin validate` 对 marketplace 和插件都通过。本版没有付费调用；生态总负责人已在临时副本里用同样的 schema 改动跑通真实 Codex 审查（completed、有 findings），本仓库没有另做真实调用。v0.8.0 列出的其余未验证项不变。

## 更新

- Claude Code：运行 `claude plugin update delegate@delegate-marketplace`，然后打开新会话或执行 `/reload-plugins`。
- Codex：如果 `~/.codex/config.toml` 里 `[marketplaces.delegate-marketplace]` 的 `ref` 固定在旧标签，把它改成 `"v0.8.5"`，再按 Codex 的方式重新安装或更新插件并重开会话。
