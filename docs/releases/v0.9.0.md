# v0.9.0：审查报告新增可复算的补丁指纹（接口 1.4）

简体中文 | [English](../en/releases/v0.9.0.md)

这是 v0.8.6 之后的次版本。**审查报告从本版起带一个与本机 git 配置无关的补丁指纹，可以在 GitHub Actions 等别的机器上复算，把审查结论绑定到具体补丁。** 接口说明从 `1.3` 升到 `1.4`，只增字段；报告 `schema_version` 仍为 `1`，命令参数和退出码不变，不需要迁移。

起因是总账 S98：autopilot 要在 Actions 上核对「这份审查审的就是这个 PR 的改动」，但原有的 `scope.diff_sha256` 是对 diff 文字算的，受仓库 `.git/config`（`diff.algorithm`、`diff.noprefix`、`diff.context`、`core.quotepath`、`core.abbrev`）、`.gitattributes` 和 git 版本影响，换一台机器就对不上。用户于 11-20 批准规格与计划（原话「批准，写英文页和 Plan」「批准，开始实现」）。原先预告给 1.4 的 `run.restore` 等三项尚未立项，顺延到下一个次版本。

## 变化

- **新增 `scope.fingerprint`**：`{"algorithm": "blob-pairs-v1", "sha256": …, "paths": […]}`。只在基准为两个提交之间（`commits`）时有值；`staged`、`unstaged`、`working-tree` 三种基准为 `null`。`paths` 与生成 diff 的被审文件集合相同，被 `exclude` 的文件不在其中。
- **算法 `blob-pairs-v1`**：第一行写版本头 `delegate-blob-pairs-v1`；每个被审路径一行，写路径、`\0`、两侧的权限和对象编号；按路径的 UTF-8 字节序排列；某一侧不存在或是目录时写 `000000` 加全零编号；对整段文本算 sha256。只用两个提交树里的事实，不用 diff 文字。完整定义、固定测试向量和复算参考见 [review-fingerprint 规格](../../spec/review-fingerprint.md)。
- **`interface.json` 升到 1.4**：`review.report` 下新增 `fingerprint`，写明字段、算法名和适用基准；其余内容不变。
- **新增固定诊断码 `fingerprint_inputs_inconsistent`**（退出 127）：取到的文件条目和被审文件对不上时报出，不输出半截指纹。
- **`scope.diff_sha256` 不变**：仍是 diff 文字的 sha256，只在本机有效。

## 使用方怎么解读

指纹一致只说明审查覆盖的补丁就是你算出的那一份，**不等于可以合并**；还要自己对比 `paths` 和 PR 实际改动的文件。遇到不认识的 `algorithm`，按无法复算处理。在 Actions 上复算时，浅克隆要能取到 `from` 提交。

## 验证与已知限制

每项行为都先写测试并确认实现前失败。新增 `test-review-fingerprint.py`（固定测试向量逐字节比对、空集合、UTF-8 字节序、64 位编号）；`test-review-context.py` 新增四项：六种改动形态（新增、删除、修改、只改权限、文件变软链接、文件变目录）与 `git ls-tree` 独立复算一致；在五项 diff 配置加属性 `-diff` 的干扰下 `diff_sha256` 改变而指纹不变；三种未提交基准为 `null`；条目不一致时报固定码。`test-review-result.py` 与 `test-interface.py` 覆盖报告字段和 1.4 接口。修复后免费总验证为 354 项 Python、53 项 shell 和 19 项 eval，循环注册的 Python 回归套增至 27 个；`claude plugin validate` 对 marketplace 和插件都通过。

**未实测不同 git 版本下结果是否一致**，这一点由算法只取树对象事实来保证。真实模型审查报告里的该字段未另行验证（付费，规格未要求）。v0.8.0 列出的其余未验证项不变。
