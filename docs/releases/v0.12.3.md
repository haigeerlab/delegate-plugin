# v0.12.3：修复 Claude Code 后端审查在 macOS 上必然失败

简体中文 | [English](../en/releases/v0.12.3.md)

## 修复 Claude Code 后端审查在 macOS 上必然失败

v0.10.0 起，`review --backend claude-code` 在 macOS 上每次都以 `failed` 结束，审查 0 个文件，诊断只有 `stream_empty_or_oversized`（v0.12.2 起另有 `backend_exit_nonzero`）。原因是监督进程从私有目录里暂存的几份代码运行，而 `review_result` 后来新增的导入（`review_recheck`、`review_context` 等）没有一起暂存；监督进程第一次检查启动事件就报 `ModuleNotFoundError`，随即清理掉刚启动的原版 CLI。

本版把启动事件检查移进只依赖标准库的 `review_init.py`，监督进程只暂存 `review_macos.py`、`review_init.py`、`claude_review.py`；访客路径的暂存清单补齐 `review_init.py`、`review_fingerprint.py`、`review_recheck.py`、`reviewer_select.py`。监督进程遇到意料之外的异常时改记固定码 `anchor_internal_error`，不再是空诊断。合同见[规格](../../spec/claude-review.md)「监督代码暂存缺模块」一节。

## 影响面

只影响 Claude Code 后端审查（macOS 原生路径与访客路径）。Codex 后端和 run 不受影响。审查行为、报告字段与接口版本（1.7）不变。

## 验证与已知限制

新增导入闭包测试：把每份暂存清单拷到隔离目录导入入口模块，并静态扫描清单内全部导入语句（含函数体内的延迟导入），修复前两份清单都失败，修复后通过；启动检查函数从 `review_result` 导出的仍是同一对象；监督进程兜底诊断有离线测试。需要 `--srt` 的真实 Mac 夹具另行运行；访客路径本机没有 Lima 环境，只做导入闭包测试。真实模型复跑在发版后用安装版进行。

本次发版准备实测：免费总验证 512 项 Python，循环注册的 Python 回归套 31 个。

## 更新

- Claude Code：运行 `claude plugin update delegate@delegate-marketplace`，然后打开新会话或执行 `/reload-plugins`。
- Codex：把 `~/.codex/config.toml` 里 `[marketplaces.delegate-marketplace]` 的 `ref` 改成 `"v0.12.3"`，再运行 `codex plugin marketplace upgrade delegate-marketplace` 和 `codex plugin add delegate@delegate-marketplace`，然后重开会话。
