# v0.5.1：修复 Claude Desktop 中 Claude 审查后端被误拒

简体中文 | [English](../en/releases/v0.5.1.md)

这是 v0.5.0 之后的修复版本，命令、参数和权限边界都不变。从 v0.5.0 升级不需要迁移。

## 修复

- **Claude Desktop 中 Claude 后端被误拒**：在 Claude Desktop 的 Code 会话里运行 `/delegate:review --backend claude-code` 或 `/delegate:doctor --backend claude-code`，必然报 `native_authentication_environment_unverified`。原因是 Desktop 会给每个会话注入 `ANTHROPIC_BASE_URL=https://api.anthropic.com`，插件把它当成了自定义 provider。现在只在它规范化后等于官方默认端点时放行：https、主机 `api.anthropic.com`（不区分大小写）、端口为空或 443、路径为空或 `/`。其他任何值，以及其他认证或 provider 变量，仍然拒绝。子进程环境本来就不继承这个变量，所以实际连接的端点不变。

## 验证与已知限制

免费总验证覆盖 162 项 Python（比 v0.5.0 多 5 项回归用例）、53 项 shell 和 19 项 eval；`claude plugin validate` 对 marketplace 和插件都通过。官方地址判断另外用 15 个边界输入做了差分检查：http、伪造子域名、带用户名、带路径或查询参数、改端口、结尾多一个点、URL 编码绕过都被拒绝。

本版没有发起任何模型调用。在 Claude Desktop 里把 Claude 后端的 doctor 完整跑通、以及真实模型审查都还未验证：验证用的机器没有安装 srt，doctor 越过认证检查后停在 `sandbox_runtime_missing`。v0.5.0 列出的其余未验证项不变。

## 更新

运行 `claude plugin update delegate@delegate-marketplace`，然后打开新会话或执行 `/reload-plugins`。版本号变化后，宿主才会替换旧的安装缓存。使用 Claude 后端仍需本机已有 srt 0.0.79，放在 `PATH` 中或用 `DELEGATE_SRT_BIN` 指定绝对路径。
