# v0.8.3：补齐使用者文档缺口

简体中文 | [English](../en/releases/v0.8.3.md)

这是 v0.8.2 之后的补丁版，**只改面向使用者的文档和帮助文字，行为不变**。接口说明仍为 `1.3`，命令参数、期限、结果行、结果文件和退出码都与 v0.8.2 相同；不需要迁移。

起因是生态总负责人为写使用手册通读各插件文档后交来的缺口清单（总账 S75）：使用者照文档做会卡住或误解的地方。逐条对照 v0.8.2 核实后，本版改了下面七处。

## 修正

- **路由技能的描述**：`delegate-routing` 的触发描述原来写「派给 Codex 或 Claude Code」，没分开审查和执行；现在写明 Codex 可审查或执行，Claude Code 只做只读审查。两份 README 的开头原本就写对了，未改。
- **`--timeout` 的后台要求统一**：README、插件 README、`references/run.md` 和脚本 `--help` 原来写「超过宿主前台期限（600 秒）才用后台」，命令说明和技能写「超过 540 秒就用后台」。现在统一为更严的说法：带 `--timeout`（541～7200 秒）就用宿主后台模式（[run-longrun](../../spec/run-longrun.md) S9）。一次运行最多约 `T + 30` 秒，按 600 秒判断会让 571 秒以上的运行撞上前台上限。
- **srt 怎么装、怎么核对**：前置条件写了「已安装的 srt 0.0.79」，但没写它来自哪个包。根 README 补上 npm 包名 `@anthropic-ai/sandbox-runtime`、安装命令和 `srt`／`node`／`claude` 的版本核对，故障排查的条件不足（127）一行指向它；插件 README 与帮助同步写明包名。
- **`--write` 不提交**：「越出沙箱的命令（如 worktree 里 `git commit`）直接被拒，提交由调用方完成」原来只在插件 README；根 README 的写入说明和参数表补上这句。
- **留作验收证据**：日志与结果文件会轮换清理（最近 50 组、链状态 14 天），原来没说要留证据该怎么办。根 README 补一段：run 复制 `<runId>.result.json` 和 `<runId>.answer`，review 保存标准输出的 JSON 报告；过程日志只摘必要几行。
- **无提交仓库的 `git_probe_failed`**：前置条件写了 review 要求已有提交，但故障排查表没有这个诊断码。补一行：退出 127、`--dry-run` 也一样，最常见原因是仓库还没有提交，`--changes working-tree --include-untracked` 也绕不过，先提交一次再审；已有提交时核对 `--base`／`--head`。
- **`/delegate:help` 分节分条**：`commands/help.md` 原来是几大段不分行的长句；现在按入口、review 范围、run、Claude 后端、结果与退出码、迁移分节，每条一行，并要求回答时照此分条。内容不减，删去与脚本 `--help` 重复的说法；Codex 转换后从 3993 字节降到 3600 字节左右，仍在 4000 字节上限内。

## 不在本版

- 生态总账里的另外两条不属于本仓库文档：本机主目录检出停在旧分支是本机状态；agent-relay 仍引用已删除的 `delegate:delegate` 由 agent-relay 修正。
- 给「仓库没有 HEAD」单独一个诊断码属于行为改动，本版不做；`git_probe_failed` 仍是所有内部 git 查询失败共用的码。

## 验证与已知限制

脚本只改了 `--help` 里一行说明文字，没有改逻辑和测试。免费总验证仍为 328 项 Python、53 项 shell 和 19 项 eval；命令体积测试通过（`help.md` 转换后约 3600 字节）；`claude plugin validate` 对 marketplace 和插件都通过。本版没有付费调用。v0.8.0 列出的其余未验证项不变。

## 更新

运行 `claude plugin update delegate@delegate-marketplace`，然后打开新会话或执行 `/reload-plugins`。从 v0.8.2 升级不需要迁移。
