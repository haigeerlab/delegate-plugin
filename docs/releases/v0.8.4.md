# v0.8.4：无提交仓库的审查报专用诊断码

简体中文 | [English](../en/releases/v0.8.4.md)

这是 v0.8.3 之后的补丁版，只改一处诊断：**还没有任何提交的仓库做 `/delegate:review` 时，报 `repository_has_no_commits`，不再报笼统的 `git_probe_failed`**。接口说明仍为 `1.3`，命令参数、退出码和报告的其他内容不变；不需要迁移。

起因是生态总负责人 11-04 实测（总账 S75 第 9 条）：新建、尚无提交的仓库做 review 只得到 `git_probe_failed`，看不出原因。v0.8.3 先在故障排查里补了说明，本版让诊断本身说清楚。

## 修正

- **新诊断码 `repository_has_no_commits`**：读取 HEAD 失败、且仓库里没有任何引用时报这个码。退出码仍为 127，报告 `execution_status` 仍为 `conditions_missing`，`--dry-run` 也一样，模型不会启动；固定提交和工作区两种范围都适用。
- **其他 git 查询失败不变**：已有提交时，`--base`／`--head` 指向不存在的提交等情况仍报 `git_probe_failed`。
- **文档**：根 README 中英文的故障排查拆成两行，分别说明两个码；`/delegate:help` 同步。

## 兼容性

`diagnostics` 不是稳定字段。报告里稳定字段 `unreviewed[].reason` 在这种情况下的值也从 `git_probe_failed` 变成 `repository_has_no_commits`；这个字段从未规定取值集合，已知使用方都不按它的值判断，所以接口版本不升。按 `git_probe_failed` 识别"仓库没有提交"的脚本要改认新码。

## 验证与已知限制

先写回归测试：无提交仓库在固定提交和工作区两种范围下都断言新码，修复前确认失败；另一条测试守住已有提交时缺失提交仍报 `git_probe_failed`。修复后免费总验证为 330 项 Python、53 项 shell 和 19 项 eval；`claude plugin validate` 对 marketplace 和插件都通过。本版没有付费调用。

当前分支没有提交、但仓库里有别的引用（例如 `git switch --orphan` 新建的分支）时仍报 `git_probe_failed`。v0.8.0 列出的其余未验证项不变。

## 更新

运行 `claude plugin update delegate@delegate-marketplace`，然后打开新会话或执行 `/reload-plugins`。从 v0.8.3 升级不需要迁移。
