# v0.5.2：Codex 审查附带行号，修正 README 说明

简体中文 | [English](../en/releases/v0.5.2.md)

这是 v0.5.1 之后的修复版本，命令、参数和权限边界都不变。从 v0.5.1 升级不需要迁移。

## 修复

- **Codex 审查附带行号**：Codex 后端收到的文件内容此前不带行号，模型只能自己数行。真实审查中，模型给出的发现 `line` 为 null，无法定位，整次审查被判 `failed`（`review_incomplete`）。现在每行内容都带 1 起始的行号前缀，提示里也写明 `findings.line` 要填对应文件的行号。快照和 SHA-256 仍按原始文件计算；“任一发现未定位即不算完成”的判定不变；行号前缀计入 1 MiB 输入上限。

## 文档

以下修正来自两次真实模型审查（Claude 后端、Codex 后端各一次），都已对照代码核实。中英文同步。

- **前置条件与快速开始**：`/delegate:review` 要求仓库已有提交，尚无提交的仓库只能用 `/delegate:run`；安装 Codex 和 ChatGPT 登录注明为 Codex 后端专属步骤，只用 Claude 审查后端时可以跳过。
- **故障排查**：`native_authentication_environment_unverified` 的核对命令改为只列变量名，不再把密钥值打到终端；“登录后仍不提议”改为说明 v0.5.0 起提议只在明确请求委托时出现；新增 Claude 后端在非 macOS、缺少 GUI launchd 域或内核接口检查失败时的诊断码与处理；写清 Codex 0.160.0、0.162.1 与 `@latest` 安装各自的含义。
- **`--model` 说明**：参数按原值传给所选后端；入口先拒绝语法非法、属于另一后端模型族的值和 Claude 的 `opusplan`（退出码 64），只有未知但语法合法的值才交给所选 CLI 判断。此前写成“非法值由 CLI 报错”，会让用户把入口拒绝误当成 CLI 或模型权限问题。

## 验证与已知限制

免费总验证覆盖 166 项 Python（比 v0.5.1 多 4 项回归用例）、53 项 shell 和 19 项 eval；`claude plugin validate` 对 marketplace 和插件都通过。

行号修复合并后，用 `main` 源码以 Codex 后端对 README.md、四个命令文件和 `spec/claude-review.md` 做了一次真实审查：6/6 个文件全部审完，`execution_status=completed`，退出码 0，唯一一条发现带有可核实的行号（README 第 161 行，即本版修正的 `--model` 说明）。修复前，同一范围的审查因发现缺少行号被判 `failed`。v0.5.0 列出的其余未验证项不变。
