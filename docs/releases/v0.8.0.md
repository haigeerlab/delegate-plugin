# v0.8.0：把一个模块整体交给 Codex 做

简体中文 | [English](../en/releases/v0.8.0.md)

这是 v0.7.1 之后的次版本。`/delegate:run` 新增结果文件、同一会话接着派任务、长任务期限、完成后检查、事先写入授权和规则片段，接口说明升到 `1.3`（只增不改）。不加新参数时，命令用法和 540 秒期限不变；stdout 与过程日志有变化，见下文“升级说明”。

## 升级说明

使用方（读 delegate 输出、过程日志或 `interface.json` 的脚本、插件、会话流程）请留意四件事：

1. **结果行前多一行。** 结果行格式不变，仍是 stdout 最后一行；它前面紧挨着多出一行 `delegate: result=<路径>`。没有结果行时（失败、中断、未能回收、空答复），这一行改打印到 stderr；结果文件写入失败时不输出这一行，stderr 改为 `delegate: 结果文件写入失败。`。按“最后一行”取结果行的流程不受影响；把“最后一行之前的全部输出”当作答复或问题正文的流程，会把这一行一起拼进去，需要把它去掉。已知 module-crew 的 offload 在 `needs-input` 时正是这样取问题正文，修订另行处理。
2. **过程日志拆成两个文件。** `<runId>.events.jsonl` 是 Codex 以 `--json` 运行的事件流，`<runId>.log` 是 stderr；失败时 stderr 打印的日志末尾随之变化，并附最近的事件。读日志文本的脚本需要调整；日志不是接口，要拿结构化结果请读结果文件。
3. **判断成功仍先看退出码。** 先看退出码为 0，再看 `status=done`。结果文件的 `status` 多了 `unmarked`（仅 `--strict`）以及没有结果行时的 `failed`、`interrupted`、`unreaped`、`empty`；遇到不认识的值要停下或当失败处理。
4. **状态文件保留 14 天。** `--resumable` 链的状态、占位和结果文件不再随最近 50 组日志一起删除，改为保留 14 天；过程日志仍按最近 50 组清理。

## 新增

- **结果文件（[run-result](../../spec/run-result.md)）**：每次启动过 Codex 的 run 写一份 JSON 结果文件，记会话 ID、状态、首行结束标记、执行过的命令与退出码、写模式下改动的文件，以及本次和整个会话的 token 用量（`usage.run` 取会话累计值的差）。新增 `--strict`：答复首行没有结束标记时判 `unmarked`、退出 1。
- **接着派任务（[run-continue](../../spec/run-continue.md)）**：新增 `--continue <runId>`，在 `--resumable` 链上状态为 `done` 的一轮之后，于同一 Codex 会话里接着做下一个任务。只读/写模式、仓库须与原运行一致，每一轮只能被接一次；结果文件记 `kind`、`parent`、`chainRoot`。
- **长任务（[run-longrun](../../spec/run-longrun.md)）**：新增 `--timeout <秒>`，把期限放大到 541～7200 秒，时间预算与收尾按 run-timeout 的公式随之放大；默认仍是 540 秒。超过宿主前台期限时须由调用方用后台模式调用，delegate 不托管后台进程。中止清理沿用 v0.7.1。
- **完成后检查（[run-check](../../spec/run-check.md)）**：新增 `--check "<命令>"`，运行以 `done` 结束后按参数列表、不经 shell 在工作区执行检查命令，结果（通过/失败/超时/无法运行、退出码、输出末尾）写进结果文件，并在 Git 验收块之前打印一行。含 shell 运算符的命令直接拒绝，规则与 module-crew S30 一致。
- **事先写入授权（run-check）**：新增 `--authorized-by <文件>`，记录写入授权的来源文件路径、sha256 和字节数；整条链须为同一文件，sha256 不一致就拒绝。delegate 不读授权内容，只核对文件与仓库。`run.write` 仍是 `"explicit"`；`delegate-routing` 的写入规则加了带 `--authorized-by` 的例外。
- **规则片段（[run-rules](../../spec/run-rules.md)）**：新增 `--rules-file <文件>`，把本次委托专用的规则原样放在前言之后；AGENTS.md 仍由 Codex 自己读取。结果文件只记规则文件的路径、sha256 和字节数，不存原文。
- **接口说明 `1.3`，只增不改**：`interface.json` 的 `run` 下新增 `result`、`usage`、`continue`、`longRun`、`check`、`writeAuthorization`、`rules` 七个能力标记，已有字段不删不改。使用方按 `>=1.3,<2.0` 且对应字段存在来启用。
- **用法说明**：`/delegate:run` 的 1.3 用法与授权纪律集中在插件的 `references/run.md`，命令说明只加一句“必须先读”。

## 验证与已知限制

免费总验证覆盖 328 项 Python（比 v0.7.1 多 75 项：run-result 31 项、run-check 17 项、run-continue 12 项、run-longrun 5 项、run-rules 5 项、接口说明 5 项）、53 项 shell 和 19 项 eval，25 个循环注册的 Python 回归套（新增上述五套；合并时漏了注册，本次发版补上）；`claude plugin validate` 对 marketplace 和插件都通过。

付费真实实测（Codex CLI 0.162.1，本机默认模型，记录见[验证记录索引](../verification/README.md)的 2026-10-27 一节）：

- **S38 前置实测**（[记录](../verification/2026-10-27-delegate-s38-probe.md)，18 次调用）：确认事件流里的会话 ID、命令与退出码、累计用量可用作结果文件来源，同一会话能接着做新任务，长期限运行能正常结束（656 秒，当时未经 `--timeout`）。
- **合并实测**（[记录](../verification/2026-10-27-delegate-1.3-merged-live.md)，4 次调用）：结果文件字段与真实事件逐项一致；`usage.run` 差值正确；`--continue` 在同一会话接着做；`--authorized-by` 记录在链上核对通过；`--check` 在真实工作区执行；带 `--strict` 时首行结束标记压过了 AGENTS.md 的相反要求；`--write` 与原运行不一致时拒绝且不调用 Codex。
- `~/.codex/config.toml` 在合并实测前后 sha256 一致。

尚未验证：

- **`--timeout` 超过 540 秒的真实运行尚未验证**（合并实测那次只跑了 500 秒），长期限下被中止时的收尾与清理也未验证；期限换算由桩测试覆盖。依赖长任务的使用方（如 module-crew 的模块外包）开用前应先补这项实测。
- 不带 `--strict` 时，AGENTS.md 若要求别的首行格式，答复首行可能不是结束标记，结果仍判 `done`。这是规格写明的限制，需要可靠标记就加 `--strict`。
- `--strict` 在其他模型、推理档下能否同样压过 AGENTS.md（只测了本机默认模型 1 次）。
- `--check` 的超时、无法运行和回收失败三种结果只在桩测试里覆盖。
- 上下文占用、压缩和额度不在结果文件里：这些只在 Codex 自己的会话文件中，1.3 不读取。

v0.7.1 列出的其余未验证项不变。
