# v0.10.0：审查发现的严重程度与复审对照上一轮（接口 1.5）

简体中文 | [English](../en/releases/v0.10.0.md)

这是 v0.9.0 之后的次版本，给「自动接管」流程用：Codex 的审查意见要分成阻断和建议，阻断返工后复审，两轮仍未解决交给人。**本版起，每条审查发现带 `severity`；复审时可以把上一轮报告交进来，逐条看上一轮的阻断解决了没有。** 接口说明从 `1.4` 升到 `1.5`，只增字段；报告 `schema_version` 仍为 `1`。不带新参数时行为不变，不需要迁移；但读报告的一方要知道 `findings` 多了一个字段（见下文）。

起因是总账 S101「自动接管」合并方案（用户 11-21 批准，原话「按推荐批准」）。delegate 这一块拆成 review-severity、review-recheck 两个模块，规格、计划与交付验收都在本会话经用户批准；用法草案见 [spec/usage/auto-takeover-review.md](../../spec/usage/auto-takeover-review.md)。

## 变化

### 审查发现的严重程度

- 报告每条发现新增必填字段 `severity`：`blocking`（阻断）或 `suggestion`（建议）。审查模型按固定判据 `severity-v1` 标注，判据由 autopr-design 起草、用户批准，全文见 [review-severity 规格](../../spec/review-severity.md)；`--task` 不能改判据，以后改判据只换新名字。
- 拿不准、但属实就该阻断的，标 `blocking` 并在 `unverified` 里写明确认不了的内容。
- 模型漏标或取值不对，整次审查判 `failed`（诊断 `finding_invalid`），delegate 不替模型补。
- 读报告的一方：`severity` 缺失（v0.9.0 及以前的报告）或不认识，一律按 `blocking`；只在 `execution_status=completed` 且有结论时才看；没有阻断不等于可以合并。

### 复审对照上一轮

- `/delegate:review` 新增 `--previous-report <上一轮报告>`。上一轮的阻断发现（上一轮本身是复审时，还包括它仍未解决的旧项）逐条进报告新字段 `recheck.items`，标 `resolved` 或 `unresolved` 并给证据；本轮 `findings` 只放新问题。合同见 [review-recheck 规格](../../spec/review-recheck.md)。
- 上一轮报告必须是 delegate 产出、已有结论、范围相同（`commits` 下 `--base` 也相同，`--head` 可以前进）。否则报 `previous_report_unreadable`、`previous_report_invalid` 或 `previous_report_scope_mismatch`，退出 127，不启动模型。模型的逐条回答不完整报 `recheck_invalid`，整次审查 `failed`。
- 本轮阻断集合 = `recheck.items` 里 `unresolved` 的 + `findings` 里按 `blocking` 处理的。轮次计数和是否交给人由调用方判断。要核对复审的是修正后的补丁，比较 `recheck.previous_fingerprint` 与本轮 `scope.fingerprint`。
- 不带该参数时 `recheck` 为 `null`。

### 接口 1.5

`interface.json` 的 `review.report` 新增 `severity`（字段、取值、判据名 `severity-v1`、缺失按 `blocking`），`review` 新增 `recheck`（参数 `--previous-report`、字段 `recheck`、状态 `resolved`／`unresolved`）。

## 验证与已知限制

每项行为都先写测试并确认实现前失败（例外在模块 todo 里逐条注明）。新增 `test-review-recheck.py`，并在 result、execution、context、cli、interface 各套件补充用例；review-severity 随合同给 5 处旧测试夹具补了 `severity`，没有改断言。免费总验证为 388 项 Python、53 项 shell 和 19 项 eval，循环注册的 Python 回归套增至 28 个；`claude plugin validate` 对 marketplace 和插件都通过。

**以下都没有实测：** 两个后端真实运行时能否接受新的输出结构（`severity` 的枚举、复审时的 `previous`）；模型按判据标注、判断「已解决」的准确度；访客路径（需要一次性虚拟机）。按用法草案，发版后用安装版实跑 U1、U2（需调用 Codex，付费）交用户判定。v0.8.0 列出的其余未验证项不变。

## 更新

- Claude Code：运行 `claude plugin update delegate@delegate-marketplace`，然后打开新会话或执行 `/reload-plugins`。
- Codex：把 `~/.codex/config.toml` 里 `[marketplaces.delegate-marketplace]` 的 `ref` 改成 `"v0.10.0"`，再运行 `codex plugin marketplace upgrade delegate-marketplace` 和 `codex plugin add delegate@delegate-marketplace`，然后重开会话。
