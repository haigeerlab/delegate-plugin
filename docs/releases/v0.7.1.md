# v0.7.1：run 中止时回收 Codex 起的命令

简体中文 | [English](../en/releases/v0.7.1.md)

这是 v0.7.0 之后的补丁版，只修 `/delegate:run` 中止时的进程清理。接口说明仍为 `1.2`，命令用法、参数、540 秒期限、结果行和状态文件都不变。

## 升级说明

使用方（读 delegate 输出的脚本、插件、会话流程）请留意两件事：

1. **新增退出码 125。** 执行进程在上限内回收不了时，`/delegate:run` 输出 `delegate: 执行进程未能回收，PID=…` 并以 125 退出，不输出结果行。按失败处理即可；仍然先看退出码为 0、再看 `status=done`。
2. **中止时 stderr 多几行清理报告。** 到期或被 TERM/INT/HUP 中止时，stderr 会多出 `delegate: 清理：…` 开头的几行：中止前 Codex 的后代清单、`无残留` 或 `仍有残留，PID=…`。stdout 和结果行不变。

## 修复

- **中止时回收 Codex 起的命令（[channel](../../spec/channel.md) 修订 S41）**：Codex 执行的每条 shell 命令都起在新会话、新进程组，原来中止时只清理 Codex 自己的进程组，命令被 init/launchd 收养后继续运行，写模式下可能在 delegate 报告结束后还在改工作区。现在中止时先冻结 Codex，沿父子关系快照全部后代，对各后代进程组和 Codex 发 TERM 并解冻，共用最多 2 秒宽限后 KILL 残余。
- **最后的等待有上限**：回收执行进程最多等 5 秒，回收不了时如实报告 PID 并退出 125，不再无限期挂住宿主。wrapper 被中断时最多等执行进程 15 秒，再强制结束并最多等 2 秒；强制结束时报告「执行进程超时未退出，已强制结束（PID=…），其后代可能残留。」。
- **清理结果如实报告**：中止时的清理报告写进过程目录的 `<runId>.cleanup`，并转发到 stderr；这个文件随所属日志一起按保留规则清理。

## 验证与已知限制

免费总验证覆盖 253 项 Python（比 v0.7.0 多 6 项：通道回归 4 项、新增的 `reap-fake-endpoint` 2 项）、53 项 shell 和 19 项 eval，20 个循环注册的 Python 回归套；`claude plugin validate` 对 marketplace 和插件都通过。回归测试先在 v0.7.0 代码上确认红灯再修复。

- 假 codex 回归：换了会话的后代在到期和 TERM、INT、HUP 中止时都被回收，且写出清理报告；`wait` 不返回时 125 有界退出；执行进程忽略 TERM 时 wrapper 有界退出并如实报告。
- 真实 Codex 0.162.1 连本机假 Responses 端点（不带凭据、临时 `CODEX_HOME`，没有调用模型）：执行长 `sleep` 时到期、TERM、INT、HUP 各一次，`zsh -lc` 与 `sleep` 都不再残留。`reap-fake-endpoint` 在本机没有 codex 时跳过。
- `~/.codex/config.toml` 测前测后 sha256 一致。

尚未验证：

- Linux 实机（`/proc` 列进程的路径）。
- 写模式（`workspace-write` 沙箱）下的回收。
- S38 实测中一次「`run_codex.py` 收到 TERM 后 60 秒不退出」的真实根因；免费条件下没有复现，需要真实 provider 与付费调用才能定位。
- Codex 正常结束后自己留下的后台进程、冻结前已被收养的进程、快照与发信号之间的 PID 复用，不在清理保证内。

v0.7.0 列出的其余未验证项不变。

## 更新

运行 `claude plugin update delegate@delegate-marketplace`，然后打开新会话或执行 `/reload-plugins`。从 v0.7.0 升级不需要迁移；按退出码判断成败的流程，请把 125 归入失败。
