# v0.7.0：run 超时保留进度，写模式不再改 Codex 用户配置

简体中文 | [English](../en/releases/v0.7.0.md)

这是 v0.6.0 之后的次版本。`/delegate:run` 超时后保留进度并输出结果行，可续跑 run 超时后能续跑，接口说明升到 `1.2`（只增不改）；`--write` 运行不再让 Codex 往 `~/.codex/config.toml` 写项目信任。不加新参数时，命令用法不变；超时时的输出有变化，见下文“升级说明”。

## 升级说明

使用方（读 delegate 输出或 `interface.json` 的脚本、插件、会话流程）请留意三件事：

1. **超时现在也输出结果行。** 以前 run 超时只有 Git 验收块；现在输出答复、元数据与 `delegate: run_id=<id> status=timeout resumable=<true|false>`，退出码仍为 124。
2. **判断成功要看退出码为 0 加 `status=done`。** 有结果行不等于成功；只看结果行是否存在、或只看 run_id 的流程要改。`statuses` 是开放集合，遇到不认识的值要停下或当失败处理，不能当成完成。只读 `1.1` 的使用方不受影响：超时仍退出 124，可继续按失败处理。
3. **`--write` 不再往 `~/.codex/config.toml` 写信任记录。** 以前第一次在某个仓库用 `--write`，Codex 会追加 `[projects."<仓库路径>"] trust_level = "trusted"`；现在只对本次运行临时信任，不落盘。旧版已经写下的条目不会被清理，需要的话自行删除。

## 新增

- **run 超时保留进度（[run-timeout](../../spec/run-timeout.md)）**：所有 run 的提示词末尾多一段时间预算。Codex 主运行最多跑总期限减去收尾预留（540 秒时为 495 秒），到阈值（540 秒时为 405 秒）后应主动停下，答复首行写 `TIME_UP:` 并写进度。可续跑 run 被强制中止后，再以只读沙箱续跑一轮只写进度的收尾（最多 45 秒）；普通 run，以及收尾超时、失败、答复为空或没有会话 ID 时，输出不靠模型的兜底文字，写模式附运行中改动的文件。普通 run 的参数（含 `--ephemeral`）不变。
- **超时后可续跑**：`--resume` 接受 `status=timeout` 的可续跑 runId；普通 run 超时不能续跑。
- **接口说明 `1.2`，只增不改**：`interface.json` 的 `run.resume.statuses` 追加 `"timeout"`，新增 `run.timeout: {"status": "timeout", "exitCode": 124}`；其余字段不变。使用方按 `>=1.2,<2.0` 判断能否续跑超时的 run。

## 行为变化

- **写模式不再写入 Codex 项目信任（[write-trust](../../spec/write-trust.md)）**：delegate 在写模式运行（普通 run、可续跑、续跑）前只读检查 `~/.codex/config.toml`，没有本仓库条目时用 `-c projects={...}` 只对本次运行临时信任。已有本仓库条目（包括 `untrusted`）时不加参数。信任键是主仓库路径，与 Codex 自己的规则一致，从 worktree 子目录运行也有效。配置文件读不了或不是 UTF-8、路径含引号或反斜杠、非常规仓库布局时不加参数，stderr 提示一行，退出码不变，此时退回旧行为。只读运行与审查的参数不变。

## 修复

- `run_codex.py` 在 macOS 上清理进程组时偶发的 `PermissionError`（EPERM）不再中断清理。

## 验证与已知限制

免费总验证覆盖 247 项 Python（比 v0.6.0 多 51 项，其中 run-timeout 26 项、write-trust 22 项）、53 项 shell 和 19 项 eval，19 个循环注册的 Python 回归套（新增 run-timeout 与 write-trust 两套）；`claude plugin validate` 对 marketplace 和插件都通过。

付费真实实测（Codex CLI 0.162.1，记录见[验证记录索引](../verification/README.md)的 2026-10-26 一节）：

- **run-timeout**（[Checkpoint 3](../verification/2026-10-26-delegate-run-timeout-cp3.md)，12 次模型调用）：真实 540 秒期限下模型在 412 秒（阈值 405 秒）主动停下，比主运行期限早 73 秒；“强制中止 → 收尾轮”完整路径跑通一次；另一模型 `gpt-5.6-terra` 也按预算停下；写模式续跑没有重复写入。
- **收尾轮长尾不罕见**：8 个样本里 2 个超过 45 秒。这时由硬期限中止收尾轮、输出兜底文字，总时长不超限，但拿不到模型写的进度。常数保持不变（规格修订 R1）。
- **write-trust**（[付费实测](../verification/2026-10-26-delegate-s36-write-trust-live.md)，1 次）：真实登录下 `--write` 在新仓库照常写入，`~/.codex/config.toml` 的 sha256 测前测后一致。[免费真机核验](../verification/2026-10-26-delegate-s36-write-trust-check.md)覆盖仓库根目录、子目录、worktree 子目录和已有 `untrusted` 条目四种情形。

尚未验证：

- 大上下文（十几万 token）会话下收尾轮的耗时；实测只构造出约 3.2 万 token。
- `gpt-6.1-sol`、`gpt-5.6-terra` 以外的模型，以及推理档 `none` 以外的档位。
- 写模式下写到一半的文件被超时打断后的续跑。
- 长尾频率只有 8 个样本，比例只能作参考。
- write-trust 的付费实测只跑了普通仓库根目录；可续跑与续跑的真实写模式运行没有付费重测（参数由桩测试覆盖）。
- 系统级、托管与项目级配置里的 `projects` 条目，以及符号链接路径的规范化。

v0.6.0 列出的其余未验证项不变。
