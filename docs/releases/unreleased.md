# 未发布变更

简体中文 | [English](../en/releases/unreleased.md)

v0.6.0 之后的 run 超时保留进度（接口 1.2）与写模式不再写入 Codex 项目信任已归入 [v0.7.0 版本说明](v0.7.0.md)。v0.7.0 之后的未发布变更如下。历史验收记录保留其发生时的版本和状态，不追认历史批准。

## 中止时回收 Codex 起的命令（S41，计划作为 0.7.1 补丁）

- **问题：** Codex 执行的每条 shell 命令都起在新会话、新进程组。`/delegate:run` 到期或被 TERM/INT/HUP 中止时，原来只清理 Codex 自己的进程组，命令被 init/launchd 收养后继续运行；写模式下可能在 delegate 报告结束后还在改工作区。
- **修复：** 中止时先冻结 Codex，快照全部后代，对各后代进程组和 Codex 发 TERM 并解冻，共用最多 2 秒宽限后 KILL 残余。最后回收执行进程时最多等 5 秒；wrapper 被中断时最多等执行进程 15+2 秒。
- **新增输出（只增不改）：** 中止时 stderr 多出几行 `delegate: 清理：…`，内容是后代清单、`无残留` 或 `仍有残留，PID=…`；执行进程回收不了时输出 `delegate: 执行进程未能回收，PID=…`，退出 **125**（新退出码，按失败处理）。wrapper 被中断时若执行进程不退出，输出「执行进程超时未退出，已强制结束（PID=…），其后代可能残留。」。过程目录多一个 `<runId>.cleanup` 文件，随日志一起清理。
- **不变：** 接口仍为 1.2；结果行 `delegate: run_id=… status=…`、stdout、状态文件、540 秒期限都不变。Codex 正常结束后自己留下的后台进程仍不在保证内。
- **验证范围：** 免费回归在 macOS 上用假 codex 和真实 Codex 0.162.1 连本机假端点（不带凭据）完成；Linux 实机、写模式下的回收、S38 T5b「60 秒不退出」的真实根因都未验证。
