这是 v0.10.0 之后的次版本。**Plan 这类快照审查（`--paths`／`--spec`／`--plan`，不带 `--base`）返工后可以带 `--previous-report` 复审了；`--spec`／`--plan` 带进来的参考文件，提示词会说明只用来核实引用。** 接口说明从 `1.5` 升到 `1.6`，只增字段；报告 `schema_version` 仍为 `1`，报告结构不变。

起因是 module-crew 反映 Plan 审查返工后一律报 `previous_report_scope_mismatch`（生态总账 S108）：快照审查的基准是 `from = to = 当时的 HEAD`，返工换了提交，而 v0.10.0 的复审要求两轮 `from` 相同。规格、计划经用户在本会话批准，合同见 [review-snapshot-recheck 规格](../../spec/review-snapshot-recheck.md)。

## 变化

### 快照审查的复审

- 两轮都是快照（各自 `from == to`）时，只比 `paths` 与 `mode`，基准提交可以前进；但上一轮的提交必须是完整编号（40 或 64 位）、在本地仓库里是提交对象（不接受标签对象），并且是本轮提交本身或其祖先。判定时不受 `refs/replace` 影响，也不会为缺失的对象联网获取。
- 一轮是快照、另一轮是区间时，一律报 `previous_report_scope_mismatch`（即使两轮 `from` 相同；v0.10.0 会放行）。
- 两轮都是区间（`--base/--head`）与未提交模式的复审规则不变。
- 快照审查没有补丁，`scope.fingerprint` 每轮相同；要核对复审的是改过的文件，比较两轮报告 `scope.files` 里的 sha256。

### 参考文件的提示

- `context_files` 不为空时，两个后端（含访客路径）的提示词都加一段固定说明：这些文件只用来核实被审文件里的引用与说法，不对它们本身提发现；同时也在审查范围里的文件照常审。为空时提示词与 v0.10.0 逐字相同。只是提示约束，校验不拦参考文件上的发现。

### 接口 1.6

`interface.json` 的 `review.recheck` 新增 `"snapshot": true`；没有这个键的 delegate 不支持快照复审。

## 影响面

- 调用方（module-crew 的 Plan 审查、autopilot）：可以对快照审查带 `--previous-report` 复审；用 `review.recheck.snapshot` 判断支持。原先把快照报告交给区间复审、且两轮 `from` 相同的做法，本版起被拒。
- 不带新参数、没有参考文件时行为不变，不需要迁移。

## 验证与已知限制

每项行为都先写测试并确认实现前失败（例外在模块 todo 里注明）。`test-review-recheck.py`、`test-review-cli.py` 用临时 git 仓库（含 SHA-256 仓库、附注标签、`refs/replace`、部分克隆）和桩后端覆盖快照复审的通过与各类拒绝；提示词在 Codex、Claude Code 与访客三条路径分别断言。

**以下都没有实测：** 真实模型是否遵守「不对参考文件提发现」；访客路径（需要一次性虚拟机）。按用法草案，发版后用安装版实跑 U3（需调用 Codex，付费）交用户判定。
