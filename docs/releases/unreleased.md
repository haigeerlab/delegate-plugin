## 审查失败定位诊断

Claude Code 后端审查失败时，报告多带几个固定诊断码，帮助定位原因：
- 探测失败时追加 `probe_stage_version`、`probe_stage_help` 或 `probe_stage_auth`，指出是哪一个探测；
- stdout 文件不见了记 `stream_file_missing`，读到的比写入的少记 `stream_read_short`；
- 审查没完成时，写过 stderr 记 `backend_stderr_nonempty`；其中审查失败（不是超时或取消）且原版 CLI 非零退出时，另记 `backend_exit_nonzero`。

原有诊断码、`execution_status`、退出码和报告字段都不变；字节数、退出码数值和 stderr 内容不进报告或日志。合同见[规格](../../spec/claude-review.md)「审查失败定位诊断」一节。

## 影响面

只影响 Claude Code 后端审查报告的 `diagnostics`。Codex 后端和 run 不受影响。`diagnostics` 属于诊断信息，接口版本仍为 1.7。

## 验证与已知限制

单元测试覆盖三个探测各自失败、stdout 缺失或读少、未完成时非零退出与写 stderr、完成时写 stderr 不加码。需要 `--srt` 的真实 Mac 夹具另行运行。本次没有用真实模型复现原失败，等发版后由遇到问题的使用方再跑一次。
