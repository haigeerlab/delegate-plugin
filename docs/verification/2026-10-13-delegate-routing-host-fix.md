# 路由修复：普通继续不再成为委托前置

日期2026-10-13；仓库 `/path/to/delegate-plugin`，分支 `codex/spec-guard-conventions-public`。LIVE-SAAS来源会话转述人类要求本会话修复delegate触发问题，本批只修真实源码；不修改安装缓存、宿主设置或LIVE-SAAS工程。

## 根因与最小修复

最新源码和旧安装报告一致：UserPromptSubmit→prompt.sh→detect --warm→route.sh；只要Codex基础缓存available就注入“决策已定、先委托确认”指针。缓存不证明宿主或委托意图，因此普通继续、Codex主会话及未知宿主都会被误导。不是Claude执行后端权限或模型调用问题。

- hooks.json移除UserPromptSubmit，保留静默SessionStart基础检查。prompt.sh/route.sh保留可执行的静默兼容入口，不读输入、不探测认证、不输出提示，便于旧注册引用新源码时安全退役。
- delegate-routing只在明确委托/分流/独立审查/执行器选择请求时使用。六类任务表改为可提议，决策已定不等于必须委托；普通继续推进已有授权工作，同一范围不重复确认，写权限仍明确授予。
- 宿主依据主会话可靠上下文，不由缓存、模型或可继承环境猜测；未知不自动建议方向。Codex可用不触发Codex→Codex提议；显式同宿主独立审查仍允许。Claude→Codex和Codex→Claude遵循用户选定后端，Claude基础条件由对应doctor核实。
- 基础事实与委托决策分开，不引入新的宿主探测器、自然语言关键词分类、会话去重状态、配置项、第三后端或Spec Guard执行器。显式命令、默认Codex、后端参数、认证、只读/写权限和生命周期实现未改。两个eval脚手架同步检查静默，而非旧JSON指针；判决器逻辑没有削弱。

中英文routing/detection合同、能力图、README和未发布说明同步。当前证据映射更新已替换测试名称及RT-01/02适用合同，历史归档与固定模型结果保持原样。
